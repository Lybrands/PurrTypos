# 小说来源库与写作方法库 UI 方案对比

## 共同设计约束

- 两页都是“我的书架”下的创作资源，不形成新的产品顶级导航。
- 应用页头左侧同时提供“首页”和“我的书架”两个明确去向，并显示当前页面名称；中间继续保留 PurrTypos 标志，右侧保留主题切换。
- 写作方法、写作方案的创建均使用项目内 `PurrModal`，不再调用浏览器原生 `window.prompt`。
- 创建方法时先选择“引导创建 / 空白创建”，再填写名称和方法类型；确认后只创建草稿。
- 页面不依赖整页滚动：列表、编辑器和来源详情在各自内容区域按需滚动。
- 来源导入仍使用 Electron/浏览器文件选择能力选择本地 TXT、Markdown；选择后的体积、分节结果和模型数据边界必须进入项目内确认界面。

## 方案对比

| 维度 | 创作资源工作台 | 书架工作室 |
|---|---|---|
| 主要布局 | 左侧列表 + 右侧编辑/详情 | 紧凑方法索引卡 + 详情条；来源书脊卡 |
| 长列表扫描 | 强 | 中上 |
| 草稿编辑效率 | 强 | 需要进入详情层 |
| 与书架视觉连续性 | 中上 | 强 |
| 分析任务承载 | 强 | 中等 |
| 空状态表现 | 中等 | 强 |
| 后续实现复杂度 | 低，接近现有结构 | 中，需要增加卡片到详情的转换 |

## 推荐结论

采用“创作资源工作台”为主方案，并吸收“书架工作室”的两个元素：

1. 来源封面/方法索引卡只用于空状态、最近使用或创建入口，不替代正式列表。
2. 保留温暖纸张、书脊色条和较轻的卡片阴影，使创作资源与书架仍属于同一产品。

不建议把所有方法永久改为大卡片网格：方法和版本数量增加后，查找、比较和编辑都会变慢。

## 推荐页面结构

### 统一页头

`首页 / 我的书架 / 当前资源库`，首页和书架均可点击。移动端收敛为首页图标、返回书架按钮和当前标题。

### 写作方法库

1. 页面标题与“新建方法”主操作。
2. “写作方法 / 写作方案”页签。
3. 左侧可滚动资产列表，显示内置/我的、草稿/已发布和版本状态。
4. 右侧固定编辑区，包含名称、类型、说明、Markdown、保存状态、版本记录与主动发布。
5. `PurrModal` 承载创建方式、名称和类型；创建成功后直接选中新草稿。

### 小说来源库

1. 页面标题与“导入文本来源”主操作。
2. 左侧只读来源列表，显示来源类型、准确版本、章节和分析状态。
3. 右侧来源详情，分离版本信息、原文入口、数据边界和分析任务。
4. “从原创作品冻结”收进导入菜单或次级弹窗，不继续占用一个永久大卡片。
5. 分析运行、审核和正式发布按来源版本展开，不把所有状态平铺成长页面。

## 实施切片

1. 先扩展共享 `AppHeader` 的首页/书架层级入口，并覆盖两页路由测试。
2. 用 `PurrModal` 替换方法和方案的 `window.prompt`，保留现有创建 API。
3. 重排写作方法库为固定双栏工作区，不改变草稿、发布和复制语义。
4. 重排来源库为来源列表/详情结构，不改变导入确认与分析安全边界。
5. 最后补空状态、移动端和 Web/Electron 实机流程。
