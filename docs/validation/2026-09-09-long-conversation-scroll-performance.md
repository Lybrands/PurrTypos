# 长对话滚动与交互修复

## 交付范围

目标是长任务运行时的滚动、点击响应，覆盖共享对话组件、小说分析事件处理与开发诊断面板。没有修改后端、PurrA 框架、真实资料或任务数据库。

## 修复

- 共享子任务列表按邻近可视范围挂载正文，缓存已测量高度；每个子任务独立 memo，查找活动由逐项 find 改为 Map。
- 执行日志及步骤组收起时卸载正文，保留既有展开状态存储。
- 诊断执行段保留已打开内容的状态并隔离离屏布局；大文本展开后才格式化，正文每块最多 4000 UTF-16 单元，通过虚拟列表呈现，避免为整份输入创建巨型文本节点。
- 删除诊断部分摘要里的重复全文序列化；复制回复的 Markdown 转纯文本延迟到点击复制时执行。
- 共享流式提交保留同步、按序的数据更新，允许 React 合并同批渲染，不再每个片段强制 flushSync。
- 小说分析新增子 Run 时只补播新成员事件，不再重放全部历史；异步事件重放按约 8ms 的计算片段让出主线程，并检查会话是否已切换。
- 历史快照最多四路读取，取得完整历史后按同一 reducer 分段重放。未通过删除事件、伪造加载完成或省略实际输出降低负载。

## 确定性验证

- 前端单元/行为测试：480 passed。
- 类型检查、基础组件边界检查、git diff --check：通过。
- 生产前端构建：通过；保留现有大 chunk 提示，不代表打包失败。
- 新增覆盖：离屏正文不挂载、高度占位、保留输入状态、新成员不重播旧输出、最多四路读取、异步与同步历史结果一致、事件重放允许交互回调执行、数据更新顺序及批量 DOM 提交。

## 独立 Electron 压力测试

运行 `npm run test:scroll-performance`。脚本使用临时用户目录与临时构建，不连接后端，不调用 Provider。窗口自动关闭，输出指标与截图到临时目录。

场景：109 个分析单元，每单元 70 段 Markdown；诊断输入格式化后约 55.5 万字符。对话从顶部跳转到底部再返回，诊断正文同样往返滚动；两个阶段共点击 160 次。

本机一次最终测量：

- 点击 160 次，界面计数 160。
- 对话同时挂载正文峰值 13/109。
- 诊断同时挂载 pre 峰值 2。
- 帧间隔 P95：9.5ms；最大：41.8ms。
- 测量区间超过 50ms 的主线程长任务：0。

这些是独立合成场景的浏览器测量，不是修复前后的真实用户对话对照，也不代表所有机器或所有数据规模都无卡顿。脚本断言响应与挂载数量，不把机器相关的固定帧时长作为单测标准。本次未新增真实 Provider 验证或真实长任务页面的性能录制。

## 使用

前端开发环境加载更新后重新打开原对话即可。无需迁移资料或重新运行整本分析。
