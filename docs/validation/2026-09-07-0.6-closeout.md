# 0.6 代码收尾与 1.0.0 基线

本次保存现有 `feat/0.6` 改动，合入 `main`，并同步到 `feat/1.0.0`、`release/1.0.0`。分支同步不创建版本标签、GitHub Release 或发布安装包。

## 收尾范围

- Obsidian 小说资料只读接入、范围准入、全文与向量检索、Agent 来源凭据，以及创作资料库界面。
- 正式来源分析在请求准备阶段进入 Planner 和持久化任务；结果追问和内部分析单元保留原有模式。
- 分析结果弹窗采用 820px 标准高度，并按视口预留上下空间；内容内部滚动，切换页签及证据视图保持高度。
- 补充默认、开启和关闭推理配置的来源分析回归覆盖。

## 验证

- `npm run check`：组件规范、类型检查、460 项前端测试、2198 项后端测试通过。
- `npm run build:web`：通过。
- `git diff --check`：通过。
- 结果弹窗在实际页面中验证了短内容、长内容、证据视图，以及 1000px、720px、600px 视口高度。
- 上述来源分析自动化使用模拟 Provider，不代表真实模型端到端复测。

## 尚未进入可分发依赖的修复

本地 Python 虚拟环境中的 PurrA 0.5.0 带有一行补丁：`AgentResponseTransaction` 构造 `AgentModelCall` 时传入 `reasoning_mode=context.requested_reasoning_mode`。修复源码及回归测试位于独立 PurrA 仓库，本仓库的 Git 提交不包含虚拟环境。

`backend/requirements-purra.txt` 仍引用公开的 PurrA 0.5.0。干净安装、CI 和打包不会携带本地补丁。用 `build-resources/backend` 中重新安装的依赖运行 `test_durable_analysis_binds_unit_runs_and_recovers_public_process[False-True-False-disabled]`，仍因最终总结未生成而失败。

因此，本地全量测试通过不代表公开依赖已修复。对开启或关闭推理的正式来源分析，底层分析任务与审核产物可完成，但最后的公开总结可能报 `model_reasoning_mode_conflict`。需要后续发布或固定包含修复的可重复安装依赖，再完成干净环境回归；不要跳过相关测试或把此代码快照当成可发布版本。
