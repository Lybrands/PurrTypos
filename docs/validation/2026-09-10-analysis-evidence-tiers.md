# 创作资料依据分档

## 已实现的规则

- 精确事实：默认 claimNature=fact。人物身份状态、知情、关系、规则、事件和伏笔继续要求精确引文。写作技法仍保留代表性引文。
- 综合资料：claimNature=summary/inference。背景、人物综合描述、阶段梗概及环境设定的归纳允许 evidence 中使用 referenceKind=chapter 和 sectionId。推断在结果及继承文档中明确标识。
- 创作内容：新增共享 Markdown 标记 purr_origin=creation，无原文引文要求。继承基线单独标记 purr_baseline_origin=source_analysis。原作分析入口拒绝 proposal 等创作性质，不能借此向原作正史写入未来设定。

章节引用从数据库读取章节标识、序号、标题和版本摘要，不读取正文、不提取引文、不做逐字匹配。引用保留来源版本与章节摘要；正式发布保留 claim_nature，依据类型随读取和续写继承返回。跨章节综合记录必须到其最晚来源章节之后才可继承。

工具 schema、分批保存、最终提交、冻结引用投影、正式发布和继承链路使用同一类型。已有带引文的结果不自动改写或降档。章节来源在 UI 中显示“来源章节”，不展示空引文。

## 验证

184 项相关后端用例通过（183 项回归后补充创作来源用例，并复跑资料存储相关测试）；26 项前端文档/对话测试通过。类型检查、基础组件检查及 diff 检查通过。

新增确定性用例验证：综合记录提交/发布不调用 validate_excerpt；章节引用短编号往返；发布重读和分叉点隔离；关键类型不能降档；创作提案不能冒充原作；分批资料可通过最终提交；新创作资料无需引文并记录创作来源。

未执行真实 Provider，对模型耗时、费用及分析准确性的变化尚无实测。未执行 Electron 桌面验收。开发只使用临时测试数据库，没有迁移或修改真实创作资料。

## 边界

分类仍依赖模型正确声明内容性质，程序不能仅凭文本可靠识别所有被错标为背景的硬规则。提示词要求将明确规则独立提取，受保护类型由程序强制精确引用。章节来源证明资料来源范围，不证明总结结论正确；推断不应被当作原文明示。

创作来源标记区分创作正文与来源分析基线，不表示对人类/模型作者身份的审计。旧文件保留原状。
