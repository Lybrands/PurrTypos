# 创作资料默认链接规则

日期：2026-09-09。

## 实现

人物、故事背景和设定资料默认采用 Obsidian wikilink 引用。小说 Agent 的计划和执行规则要求：修改关系时先读取目标资料，使用返回的 `materialLink`，关系含义写在正文；删除关系时移除对应引用。不为小说正文加链接，不改只读继承基线，不凭链接推断角色知情或资料适用范围。

读取人物和设定的列表/详情返回可直接使用的链接。链接形式为 `[[资料/人物/名字--唯一标识|名字]]`，使用本作品真实文件路径，避免仅按标题链接到虚构文件。背景读取同样提供其链接。

保存层在现有文件事务内将显式 `[[标题]]` 解析为当前作品唯一目标路径，保留别名和标题/块定位。项目创建、修改和 Agent 提案接受均使用同一规则；Agent 修改提案在展示前完成相同解析，仍需经过既有接受流程。普通正文、代码示例、注释和转义引用不自动加关系。同名标题拒绝猜选，要求使用读取到的准确链接。未找到目标的引用保留为未解析引用，不自动创建资料，不查询其他作品。

外部编辑读取先按稳定资料 ID 同步路径，因此后续新引用可使用重命名后的路径。不会批量重写其他笔记中已有的旧链接，也不实施新的重命名级联机制。关系图边来自 Markdown 引用，关系语义由 AI/作者决定；保存层不做自然语言关系推断。

共享库的检索根目录在 `资料` 下，Obsidian 的仓库根目录在其父级，索引补齐了这一前缀差异，仅对实际共享绑定生效；链接可解析不改变来源准入、章节范围或知情范围。

## 验证

- 定向回归：134 passed，包含共享文件、资料索引、小说提示词、工具执行和上下文测试。
- 后端全量回归：2,298 passed（166.13 秒）；最后合并重复绑定查询后，共享资料和索引定向复验 48 passed。`git diff --check` 通过。
- 新增案例验证：人物/背景/设定写入与 SQLite 投影一致、移除引用、同名拒绝与明确路径选择、作品隔离、外部重命名后新引用、代码与注释保护、别名和定位、幂等、Agent 提案未接受不落盘、接受后索引解析到实际目标。
- 仅使用临时测试数据库及资料目录，没有批量改写用户现有资料。
- 未调用真实 Provider，不能宣称模型每次都会正确识别关系；未进行本次 Obsidian 图谱桌面点击验收。
