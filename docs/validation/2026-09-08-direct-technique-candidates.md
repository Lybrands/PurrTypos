# 直接提炼写法候选：v1.9

## 验证范围

可执行写法的提炼前移到首次读取原文的阶段。改动范围为来源分析与技法生成指令，不包含续写继承。保留当前事实提取字段，包括同期增加的 background/location/faction/item 等类型。

## 当前职责

- 提取：facts 保持故事事实；craftCards.bodyMarkdown 直接表达有证据支持的可执行写法，包括必要的创作需要和具体文字安排。证据仍独立关联，不另交一份重复的观察分析，不生成具体续写剧情或文件目录。
- 归一：合并操作和适用条件等价的候选，保留局部范围与证据；不重新逐条提炼，不把不同场景的写法强行统一。
- 概览：继续只生成 storyOverview，不重新加工候选。
- 技法交付：选择、去重和组织成立的候选，形成 SKILL.md 及必要辅助文件。可修正不成立的解释，不能将“不重新提炼”理解为免除证据判断。

接口继续沿用 craftCards、观察目录和 contentDigest，不增加新的中间产物、固定栏目或模型阶段。工具所称“观察”现在承载写法候选及证据；此为内容职责变化，不是证据校验能力升级。提示词版本为 writing-techniques/v1.9，阶段指令继续进入运行输入摘要。

## 验收边界

离线回归验证现有数据提交、证据定位、归并保留、草稿及文件封存仍可运行；不以断言提示词出现某句话代替行为测试。真实质量和消耗尚需相同来源的前后对照：

1. 首次提取的候选是否已能指导具体写作，而非泛泛评价或剧情摘要；每项依据能否支持建议的范围。
2. 最终文件是否保留候选的有效操作和条件，且不会把局部句长或场景安排变成全书强制风格。
3. 纯技法独立使用仍不依赖原文；续写场景允许按权限补读历史，但不得以要求重读原文替代写清方法。
4. 比较整条流程的输入、输出及推理 token、调用次数、失败重试和耗时，同时记录质量问题。前移提炼可能增加提取阶段成本，不能只看最后一阶段下降。

旧的只含描述性观察的夹具与历史 Run 不能冒充 v1.9 新提取产物；端到端比较需从同一原始材料重新提取。既有结果不自动改写或重生成。
