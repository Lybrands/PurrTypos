# 执行状态胶囊与对话执行面板职责修复

## 背景

统一输出重构后出现了两个关联回归：输入框上方的执行状态胶囊无法稳定出现；对话执行面板在执行过程中显示了“第 X/Y 步”或“已完成 X/Y 项”。两者来自同一个职责混淆：任务进度与操作日志被当成了同一种展示状态。

## 设计边界

### 输入框上方的执行状态胶囊

- 胶囊是任务进度的唯一展示入口，仍通过 `AgentComposer.floatingContent` 位于输入框上方。
- 胶囊读取当前 Assistant 回合的规范任务计划。
- `planned`、`running` 或 `paused` 计划自身可以证明任务仍需展示；不得因为异步 Conversation Snapshot 暂时没有处于 running 而隐藏。
- 少于三个可见步骤时仍不显示胶囊；隐式 `Respond` 步骤仍不计入。
- 计划进入 `done`、`failed`、`blocked` 或 `canceled` 且最终输出结束后，胶囊消失。
- 规范 `long_task.progress` 可以投影为胶囊计划，但不得进入 Assistant 正文或执行过程时间线。

### 对话执行面板

- 执行期间只展示折叠入口、运行状态和计时：`正在进行 · X秒`。
- 执行期间不在面板标题显示当前步骤、步骤总数或完成数量。
- 具体操作日志继续保存在折叠面板中，不新增 LongTask 单元行；用户手动展开时只看到真实模型、工具、校验、压缩和子 Agent 操作。
- 回合结束后，面板标题显示 `执行了 X 个步骤 · 用时`，展开后显示具体操作。
- 任务步骤进度只属于输入框胶囊，操作执行记录只属于对话执行面板。

## 状态流

1. PurrA 规范输出产生 `run.todos_updated`、`run.todo_updated` 或 `long_task.progress`。
2. 共享规范输出归约器生成任务计划读模型，但不生成 Assistant 文案或操作日志行。
3. 共享任务计划选择器根据当前 Assistant 消息和计划自身状态决定是否显示胶囊；外部 loading/running 只作为计划尚未到达时的辅助信号。
4. 规范 operation、commentary、delegation 和 context-compaction 事件独立生成对话执行面板时间线。
5. 最终输出结束后，胶囊卸载；执行面板保留终态摘要和可折叠操作记录。

## 回归测试

- 仅收到 `long_task.progress` 且 Snapshot 尚未标记 running 时，输入框胶囊仍能取得活动计划。
- 活动计划少于三个可见步骤时仍隐藏。
- 终态计划且输出已结束时胶囊隐藏。
- 执行面板活动标题恒为 `正在进行`，不含步骤序号或完成数量。
- LongTask 进度不会出现在 Assistant 时间线或执行面板操作行中。
- 回合结束后仍显示执行步骤总数、耗时和原有具体操作记录。

## 非目标

- 不改变 PurrA 规范输出协议。
- 不恢复旧的 screenplay chunks/events 双存储。
- 不向执行过程添加宿主编排文案。
- 不改变具体操作的计时与终态持久化规则。
