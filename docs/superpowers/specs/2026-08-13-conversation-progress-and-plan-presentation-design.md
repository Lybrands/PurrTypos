# 对话进度与执行计划呈现设计

## 目标

修复共享 Agent 对话组件中的四项体验问题：

1. 活跃执行日志标题“正在进行”后不再显示动画省略号。
2. 用户发送消息后，立即把该条用户消息固定到对话视口顶部，不等待 Assistant Turn 或 Run 标识出现。
3. 执行过程保留公开过程说明、真实工具调用、上下文压缩和内部委派；隐藏宿主内部的输出校验 Operation。
4. 剧本耐久任务继续使用宿主编译的确定性执行 DAG，但向前端提供有业务含义的步骤标题，避免多个步骤都显示为“生成内容”。

## 非目标

- 不公开模型私有 reasoning。
- 不让 LLM 直接控制耐久任务的依赖关系、重试策略或并行度。
- 不隐藏上下文压缩或内部委派。
- 不在通用前端组件中复制剧本业务步骤映射。

## 交互设计

### 活跃执行日志

执行日志标题保持“正在进行”，继续显示加载状态与已用时间，但移除标题尾部独立渲染的 `...`。工具行、上下文压缩行和委派行自身的状态表达不在本项范围内。

### 发送后的视口固定

当前实现以新 Assistant Turn 为触发源，因此必须等 Assistant 消息获得稳定身份后才把前一条用户消息滚动到顶部。

新行为以稳定的用户消息身份为触发源：

- 会话首次恢复只记录当前用户消息游标，不触发滚动。
- 新用户消息追加后，立即以该消息索引执行 `align: start`。
- 随后创建 Assistant 消息、绑定 Run 或收到流式更新时，不重复固定。
- 编辑并重发旧消息仍视为一个新 Turn，固定替换后的用户消息。
- 用户主动向上滚动后的跟随策略保持不变。

### 执行过程筛选

共享执行时间线保留：

- 模型公开 commentary；
- `tool` Operation 和旧协议工具段；
- `context_compaction`；
- `delegation`。

共享执行时间线隐藏：

- `model` 生命周期 Operation；
- `validation` Operation。

筛选发生在规范事件到用户时间线的投影边界。持久化事件和诊断信息保持完整，避免影响恢复、耗时统计和开发诊断。

## 执行计划来源与标题

剧本任务采用两阶段编排：

1. LLM Planner 解释用户意图、范围和目标交付物。
2. 剧本宿主根据已验证意图编译 Part Manifest 和确定性执行 DAG，定义依赖、并行度、重试和校验。

截图中的重复“生成内容”不是 LLM 重复规划，而是前端把多个 `generate_document_section` 单元回退成同一个通用标题。

本次不改变计划所有权。剧本 Manifest 编译器为每个 Part 写入稳定的展示标题，例如：

- 读取原作内容；
- 分析人物；
- 梳理故事；
- 分析世界观；
- 提炼主题；
- 评估改编风险；
- 检查分析结果；
- 生成回复。

通用 LongTask 进度事件仅透传宿主提供的展示标题；共享前端优先使用该标题，缺失时继续使用现有类型回退。这样保持 PurrA 业务无关，也避免前端硬编码剧本语义。

## 数据流

```text
用户发送消息
  -> 对话状态追加 user message
  -> 视口识别新的稳定 user Turn
  -> 当帧固定该消息到顶部

LLM 解析剧本意图
  -> 宿主编译 Manifest / DAG / displayTitle
  -> LongTask 进度事件透传 title
  -> 前端规范化计划
  -> 任务进度显示语义标题

规范 Run 事件
  -> 持久化完整 Operation
  -> 用户时间线过滤 model + validation
  -> 展示 commentary / tool / compaction / delegation
```

## 测试策略

- ExecutionLog 组件行为测试：活跃标题不含 `...`。
- 滚动策略单元测试：新用户消息立即产生 anchor；Assistant/Run 更新不重复产生 anchor；首次恢复不滚动。
- 时间线测试：`validation` 不可见，`tool`、`context_compaction`、`delegation` 保持可见。
- Manifest/LongTask 投影测试：源分析各单元携带并显示不同的语义标题。
- 运行共享前端单测、剧本验收测试、TypeScript 检查和 `npm run check:agent-refactor`。

## 验收标准

- 活跃执行日志只显示“正在进行”，没有尾随省略号。
- 点击发送后，不需要等待 Assistant 消息或 Run ID，用户消息即固定到视口顶部。
- 执行日志中不出现“校验输出”，但上下文压缩、内部委派和工具调用仍可见。
- 源分析计划不再出现多个无法区分的“生成内容”，并且执行 DAG 仍由宿主确定性编译。
