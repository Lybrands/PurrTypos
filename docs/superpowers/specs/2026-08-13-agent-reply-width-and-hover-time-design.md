# Agent 回复宽度与时间展示设计

## 目标

修复共享对话组件中助手回复主体按内容宽度收缩的问题，并降低消息脚注的常驻视觉噪音。该行为同时作用于书籍对话页和剧本项目页。

## 已确认行为

- 助手回复主体、执行记录、错误或终止状态横向铺满助手消息的可用宽度。
- 助手脚注仍保持左对齐，用户脚注仍保持右对齐。
- 当前最新助手回复仍在运行时，不显示模型名称和时间；回复完成、失败或终止后才显示元数据。
- 已完成的历史助手回复不受新一轮运行影响，模型名称保持常显。
- 用户与助手消息的时间都只显示本地时间 `HH:mm`，不显示日期或月份。
- 时间默认隐藏，仅在消息 hover 或键盘聚焦时显示。
- 助手脚注顺序为“模型名称 → 操作按钮 → 时间”，时间位于操作按钮右侧。
- 最新一条助手回复的操作按钮保持常驻；历史助手回复的操作按钮仍仅在 hover 或键盘聚焦时显示。
- 用户消息的操作按钮仍仅在 hover 或键盘聚焦时显示。

## 实现边界

- 在共享 `ConversationViewport` 样式中将助手消息交叉轴对齐从 `flex-start` 改为 `stretch`；已有脚注通过自身 `align-self` 保持左对齐，不给每种回复内容分别补宽度。
- `messageMetadata.ts` 的时间格式化始终返回 `HH:mm`。
- `ConversationViewport` 从当前消息列表中显式计算最后一条助手消息的索引，不使用容易受虚拟列表、系统消息或附件影响的 CSS `:last-child`。
- `ConversationViewport` 仅在助手回复既是消息列表最后一条、会话又仍在运行时视为未结束，并通过 `metadataVisible` 显式传给 `MessageFooter`；后面已有新用户消息的助手回复属于历史回复，不受当前运行状态影响。
- `MessageFooter` 接收 `actionsPersistent` 和 `metadataVisible`，将模型名称、操作按钮和时间保持为三个有序区域；元数据可见时模型名称常显、时间由 hover/focus 控制，操作按钮仍由 hover/focus 或 `actionsPersistent` 控制。
- 用户脚注没有常显元信息时仍保留可访问的 hover/focus 入口。
- 不修改持久化数据、消息协议或书籍/剧本业务组件。

## 验证

- 先用现有页面宽度测量作为失败基线：助手回复主体当前仅占消息宽度约 48%。
- 增加时间格式和脚注结构回归测试，确认旧日期格式及常显时间会失败。
- 修复后验证书籍页、剧本页与 700px 窄屏：回复主体铺满、脚注方向不变；运行中的最新回复不显示模型和时间；结束后模型名称出现，时间位于按钮右侧且仅在 hover/focus 时显示；最新助手操作常驻、历史助手操作保持 hover/focus 显示，且无横向溢出。
