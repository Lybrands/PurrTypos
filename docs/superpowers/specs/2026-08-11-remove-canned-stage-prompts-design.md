# 剧本 Agent 自动文案与执行记录简化设计

日期：2026-08-11

## 目标

剧本 Agent 的自动阶段按钮只表达用户实际触发的简短动作，不再把宿主编排的长篇自然语言伪装成用户消息写入回复面板、Planner 输入、持久化对话或历史重放。

Agent 可以根据真实项目状态生成一段简短的后续执行概述。该概述必须由模型实际生成；模型没有生成时保持空白，不使用宿主固定文案兜底，也不因此阻止任务执行。

回复面板中的连续执行记录只保留一层披露控件。折叠时显示执行步骤数量和耗时，展开后直接显示真实步骤，不再出现“已完成/用时 -> 执行了若干步骤 -> 已操作 -> 真实步骤”的多层嵌套。

任务进度胶囊在串行执行时显示当前步骤序号，在实际并行时显示完成数量。胶囊只属于当前仍在执行或仍在输出最终总结的回合；最终总结完整结束后立即消失，不作为历史回复内容保留。

## 非目标

- 不隐藏用户自由输入的自然语言请求。
- 不隐藏模型实际生成的公开执行概述。
- 不取消自动阶段按钮，也不把按钮点击变成不可追溯的后台操作。
- 不放松审阅输入、版本身份、审阅维度、场景身份或候选稿校验。
- ~~不引入新的结构化按钮命令协议；当前阶段先复用现有对话 Turn 协议。~~ 该阶段性非目标已被《剧本 Agent 意图恢复与阶段命令设计》取代：正式按钮现在通过同一 Turn 携带类型化 `stageCommand`，仍不恢复长篇固定文案。
- 不改变后端工具事件、任务步骤状态或并行调度协议。
- 不通过 CSS 隐藏仍然存在的多层展开结构。

## 当前问题

`stageAgentStarter()` 根据项目阶段生成一段完整任务说明。它同时被用于：

1. 新会话的输入框预填；
2. 自动阶段按钮提交的 `userContent`；
3. Planner 的原始用户请求；
4. 对话快照、任务目标和历史重放。

Planner 随后根据这段宿主文案生成 `executionSummary`，容易形成近义复述。即使公开概述本身来自模型，用户看到的仍是宿主先规定措辞、模型再改写的死板对话。

此外，当前 Planner 校验要求 `executionSummary` 必须非空。模型没有提供公开概述时，任务会失败，而不是安静地继续执行。

执行记录当前有三层披露结构：

1. `WorkLog` 使用“已完成/用时”作为外层展开项；
2. `WorkLogStepGroup` 再使用“执行了 N 个步骤”作为中层展开项；
3. 每个 `ToolCallStatus` 使用“已操作：……”作为内层展开项，展开后才看到真实步骤。

连续工具批次虽然已经在时间线上归并，但展示层仍保留重复摘要和独立展开状态。用户需要连续点击多次才能看到具体执行内容。

任务进度胶囊目前无论是否串行，都以“已完成 X/N”描述进度。串行任务的真实认知是“当前进行到第几步”；只有多个步骤同时运行时，完成数量才比单一步序更准确。

## 采用方案

采用“简短用户动作 + 可选模型概述 + 后端硬约束 + 单层执行记录”。

### 简短用户动作

所有自动阶段按钮只提交与按钮语义一致的短动作，例如：

- `分析原作范围`
- `制定创作简报`
- `设计分集结构`
- `生成场景表`
- `继续创作下一集`
- `连续创作接下来 3 集`
- `审阅当前剧本`
- `重新审阅`
- `开始修订`
- `开始复审`

这些文字是用户点击动作的记录，不承担业务规则、上下文装配或执行约束。需要动态范围时只保留不可缺少的范围信息，例如集数。

新建或重新打开空会话时，输入框保持为空；不再用自动阶段文案预填输入框。用户自由输入仍按原协议提交和展示。

### 可选模型概述

Planner 仍可输出 `executionSummary`，并将其作为模型拥有的公开执行概述投影为 `commentaryDelta`。

`executionSummary` 改为可选：

- 非空且合法时原样展示；
- 缺失或仅包含空白时不展示；
- 公开投影最多保留 600 个字符，超出部分不进入对话；
- 不添加固定前缀、后缀或替代文案；
- 缺失概述不触发修复调用，也不阻止合法 Intent 执行。

`action`、`instruction`、`scope`、`constraints`、`preserve`、`requestedDeliverable` 和 `reply` 仍必须满足现有 Intent 协议。普通问答仍要求合法 `reply`。

### 业务规则归属

删除长篇自动文案不能删除业务约束。约束由现有剧本领域链路负责：

- Resolver 从项目当前 Head 选择权威交付物和范围；
- Review Manifest 绑定当前不可变 `screenplayDraft` Revision；
- 每集先生成带内容摘要的 `reviewInput`，审阅子任务只能使用该输入；
- `REVIEW_DIMENSIONS` 固定覆盖 `continuity`、`character_arc`、`structure_rhythm`、`dialogue` 和 `format`；
- 五个维度必须共享同一 `reviewedDraftId` 与正文摘要；
- 旧审阅报告不作为新一轮审阅输入；
- 校验、发布和最终回答仍以持久化任务事实为准。

因此，“不得沿用旧报告”“必须使用可验证正文”“检查五个维度”不再依赖用户消息中的提示词。

### 单层执行记录

时间线仍按照公开模型说明切分连续操作组，但每个连续操作组本身成为唯一的披露控件：

- 一个操作也必须形成操作组，不再退回单独的 `ToolCallStatus` 摘要；
- 多个相邻操作在没有公开模型说明时合并为同一操作组；
- 折叠状态显示 `执行了 N 个步骤 · 12秒`；
- 执行中显示 `正在执行 X/N 个步骤 · 4秒`；
- 展开后直接显示 `已完成 读取人物资料`、`正在执行 检查人物弧光`、`待执行 写入候选稿` 等真实步骤；
- 错误图标、步骤错误状态和耗时保留在这一层及其叶子步骤上；
- 删除 `WorkLog` 的外层“已完成/用时”披露和主回复路径中 `ToolCallStatus` 的“已操作”披露；
- 公开模型说明仍作为操作组边界，显示在前后两个操作组之间。

去嵌套必须发生在时间线投影和组件结构中，不使用 CSS 隐藏，也不保留不可见的第二层展开状态。

### 任务进度胶囊

任务胶囊继续读取当前 Assistant Turn 的可见任务步骤，进度文案按实际运行状态决定：

- 恰好一个步骤处于 `running` 时，显示该步骤在可见步骤中的位置，例如 `任务进度 · 第 3/6 步 · 检查人物弧光`；
- 多个步骤同时处于 `running` 时，显示并行数和完成数量，例如 `任务进度 · 并行 3 项 · 已完成 2/6`；
- 尚未出现 `running` 步骤但任务仍处于准备状态时，使用下一个可见步骤的位置；
- 所有步骤完成、最终总结仍在流式输出时，可显示 `已完成任务 · 已完成 6/6`；
- 最终总结完整结束并退出 `loading` 状态后，胶囊立即消失；
- 已完成历史消息不重新显示任务胶囊。

“是否并行”由当前 `runningSteps.length > 1` 判断，不根据任务名称、步骤类型或最大并行配置猜测，也不增加新的协议字段。

## 数据流

自动阶段操作的数据流为：

```text
用户点击阶段按钮
  -> 前端生成简短动作和必要范围
  -> 创建并持久化 User Turn
  -> Planner 结合动作、项目状态和对话历史生成 Intent
  -> 若模型生成 executionSummary，则公开展示
  -> Resolver 和 Manifest 根据权威项目状态确定任务
  -> 执行器按领域契约收集证据、生成、校验和发布
```

模型未生成公开概述时，数据流中省略 `commentaryDelta`，其余步骤不变。

执行记录的展示流为：

```text
结构化操作事件
  -> 归一化为真实叶子步骤
  -> 按公开模型说明切分连续操作组
  -> 每组生成唯一的“执行了 N 个步骤”披露控件
  -> 展开后直接渲染叶子步骤
```

## 前端改动边界

- 用短动作生成函数替代 `stageAgentStarter()` 的长篇任务说明。
- 空会话不再通过 `setAgentPrompt()` 注入阶段默认文案。
- 主阶段按钮、审阅面板动作和批量创作范围共用同一套短动作生成逻辑。
- 对话中的 User Turn 继续显示实际提交的短动作，保留历史可读性和编辑能力。
- 不通过字符串黑名单隐藏已经生成或持久化的内容。
- `groupConsecutiveWorkSteps()` 对单个和多个连续操作统一生成操作组。
- 主回复面板不再使用可展开的 `WorkLog` 包裹操作组，也不再为组内工具批次渲染可展开的“已操作”摘要。
- 真实工具步骤行复用同一状态、图标、错误和耗时语义，避免新建第二套工具状态模型。
- `TaskPlanCard` 的串行文案使用当前步骤在可见步骤中的索引；并行文案继续使用完成数量。
- `getActiveTaskPlan()` 继续以当前回合的 `loading` 状态作为胶囊可见边界，最终总结完整结束后返回空。

## 后端改动边界

- Planner 指令把 `executionSummary` 定义为可选公开概述。
- Intent 校验不再要求非空 `executionSummary`；概述不参与业务 Intent 的成败判断。
- Structured Call 仅在模型确实生成非空概述时投影公开文本，并对公开投影应用 600 字符上限。
- 不增加宿主概述兜底，不从动作、阶段或任务状态拼接 Assistant 自然语言。
- 审阅 Resolver、Manifest、Evidence 和校验规则保持权威，必要时增加回归断言而不复制提示词。

## 错误和恢复

- 模型未生成 `executionSummary`：继续执行，不显示开场概述。
- 模型生成过长概述：公开文本在 600 字符处停止，Intent 其他字段合法时继续执行。
- Intent 的动作、范围或交付物不合法：沿用现有修复或失败流程，不用固定自然语言掩盖错误。
- 自动动作无法满足当前项目先决条件：由 Resolver 返回真实领域错误。
- 暂停、恢复和历史重放只恢复已经持久化的短用户动作、真实模型概述、结构化操作和最终回答。
- 连续操作组在实时流和历史重放中必须得到相同的步骤数量、分组和展开内容。
- 最终总结流式输出期间保留任务胶囊；收到正常终态并完成总结提交后隐藏胶囊。

## 测试要求

### 前端

- 空会话输入框不包含阶段模板文案。
- 每个自动阶段按钮只提交对应短动作。
- 批量创作动作保留准确集数，不附加任务说明。
- 自动 User Turn 在实时和重放中显示相同短动作。
- 生产代码中不再保留被删除的长篇阶段模板。
- 单个工具批次也只产生一层“执行了 N 个步骤”披露控件。
- 多个无模型文案隔断的工具批次合并后，展开直接显示所有真实步骤，不出现“已操作”子项。
- 模型公开说明正确切分前后两个操作组。
- 串行计划显示当前步骤序号，即使当前步骤索引与已完成数量不同。
- 多个步骤同时运行时显示并行数和已完成数量。
- 最终总结流式输出期间胶囊仍可见，总结完成并退出 `loading` 后胶囊消失。
- 历史消息不显示任务进度胶囊。

### 后端

- Planner 返回空或缺失 `executionSummary` 时，合法 Intent 可以继续执行。
- 非空 `executionSummary` 仍按模型原文投影一次。
- 空概述不会生成 `commentaryDelta` 或固定替代文案。
- 过长概述最多公开 600 个字符，且不影响合法 Intent 执行。
- 重新审阅仍绑定当前不可变 Draft Revision，覆盖全部已有剧集与五个维度。
- Review Evidence 不包含上一份审阅报告，五维结果必须共享同一正文身份与摘要。

### 回归门禁

- 禁止自动阶段长文案重新进入生产对话代码。
- 禁止以固定文案补齐缺失的模型公开概述。
- 禁止仅通过前端过滤掩盖后端已经持久化的宿主文案。
- 禁止主回复执行记录重新出现多层披露或“已操作”中间摘要。
- 禁止用当前步骤序号表达实际并行任务的完成进度。

## 验收标准

1. 打开新的剧本 Agent 会话时，输入框为空。
2. 点击任一自动阶段按钮后，用户消息只显示简短动作和必要范围。
3. Assistant 的开场概述若存在，必须来自本轮模型输出，而不是宿主模板或状态拼接。
4. 模型没有生成概述时，对话直接进入结构化执行记录，不出现替代文案，任务也不因此失败。
5. 重新审阅仍使用当前可验证正文，覆盖全部已有剧集和五个审阅维度，且不读取旧报告意见。
6. 刷新、暂停和恢复后，不会重新出现已删除的长篇模板。
7. 每个连续操作组只有一层展开项，展开后直接看到真实步骤。
8. 串行任务胶囊显示当前第几步；并行任务胶囊显示并行数和已完成数量。
9. 最终总结完整输出后，任务进度胶囊消失，历史回复中也不重新出现。
