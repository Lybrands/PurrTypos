# 长任务租约与模型客户端生命周期修复设计

## 背景与证据

目标任务的第一次模型请求已经成功接收 766 个流式数据块，因此不能把失败归因于普通网络中断。该 Run 的执行心跳最后停在 05:22:26，随后在 05:24:35 被孤儿任务监控器以 `execution_lease_expired` 主动终止。紧接着的两次请求在 1.2 秒和 1.4 秒内报 `APIConnectionError`。

现有执行心跳与业务持久化共享单个 SQLite 连接；业务事务占用连接时，心跳无法独立续租。OpenAI 兼容适配器每次请求还会创建新的 `AsyncOpenAI` 客户端，但流式资源所有者只关闭底层 stream，没有关闭 client；非流式调用也没有 `finally` 清理。这两个生命周期缺陷共同解释了“先误判失联，再在立即重试时连接异常”的时间线。

## 选定方案

采用独立控制面数据库连接处理 Run 租约和孤儿回收，模型内容及业务数据仍使用现有主连接。控制面连接指向同一个 WAL 数据库，但其连接锁与业务连接隔离，使心跳不会因主连接上的长事务排队。

应用 lifespan 创建并初始化控制面连接，将其注入 `AgentComposition` 的 `SqliteExecutionLeaseStore`，并交给孤儿 Run 监控器。关闭应用时先停止监控与后台 Run，再关闭控制面连接。测试或未显式注入时保留使用主连接的兼容路径。

模型适配器必须拥有其创建的客户端：流式调用把 client 与 raw stream 一并交给 `OwnedAsyncIterator`，无论正常完成、异常还是取消都按顺序关闭；在建立 stream 之前失败时立即关闭 client。非流式调用使用 `try/finally` 关闭 client。标题生成等同类一次性客户端调用应用相同规则，避免继续积累泄漏。

## 失败处理与可观测性

租约续期失败不能静默结束。执行会设置持久取消信号，并记录不含请求正文和密钥的控制面诊断，包括失败阶段和异常类型。模型异常诊断保留 SDK 外层类型与直接 cause 类型，使后续可以区分连接池关闭、DNS、超时和协议错误；错误消息继续使用现有脱敏边界。

长任务现有的 5 秒、20 秒退避保留，它只负责短暂上游失败，不承担租约和资源泄漏的修复职责。

## 测试设计

1. 使用两个指向同一临时数据库的连接，在主连接持有长事务时验证控制面连接仍能续租，且孤儿监控不会误终止活跃 Run。
2. 用可观察的假客户端覆盖流式正常完成、建流失败、消费中取消和非流式完成，断言 client 恰好关闭一次。
3. 验证客户端清理失败不会覆盖原始模型结果或原始异常。
4. 运行 Run execution、模型适配器、长任务和应用 lifespan 的相关回归测试，再执行完整后端测试与前端类型检查。

## 范围边界

本修复不调整模型超时、内容批次大小、SQLite 业务事务结构或长任务 UI；不通过延长租约掩盖续租阻塞；不持久化 API 密钥、请求正文或未经脱敏的服务端响应。
