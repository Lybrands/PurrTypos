# Agent 执行过程面板恢复设计

## 背景

提交 `f573306` 为消除“执行步骤 → 已操作 → 真实步骤”的重复展开层，删除了外层 `WorkLog`。这同时删除了用户需要的单一执行过程面板、运行计时和结束后自动折叠生命周期。当前页面只有存在可见工具操作时才渲染步骤分组，因此任务刚开始、尚无工具事件或只有过程输出时，整个执行过程面板都会缺失。

## 目标体验

每个 Assistant 回合只保留一个执行过程面板：

- 回合开始后立即出现，默认展开，标题显示“正在进行”及实时用时。
- 工具、上下文压缩、子 Agent 和模型过程说明都作为面板内的直接内容展示。
- 不再出现第二层“已操作”“正在操作”或逐组折叠项。
- 最终输出可展示时，执行过程面板自动折叠并保留在最终输出之前。
- 结束后的标题显示本轮可见执行步骤总数和总用时；没有可见步骤时只显示总用时。
- 用户可以随时手动展开或折叠；手动选择在该回合后续重渲染中保持稳定。

## 组件边界

恢复 `WorkLog` 作为唯一 disclosure，继续由它负责：

- 运行计时；
- 展开状态；
- 从运行中到最终输出的自动折叠；
- 错误状态；
- 完成后的步骤数与用时摘要。

`AssistantMessageBody` 负责计算本回合是否正在流式执行、是否已有最终输出、可见步骤总数，以及传给面板的过程内容。现有工具叶子行继续由 `ToolCallStatus` 直接渲染。

删除 `WorkLogStepGroup` 这一层 disclosure。连续操作仍可在时间线模型中保持分组，以便计算顺序和进度，但渲染时直接输出组内的工具、上下文和子 Agent 行。模型过程说明继续作为同一面板内的直接兄弟内容，不创建新的折叠层。

## 生命周期

1. Assistant 回合进入流式状态时，即使还没有工具事件，也渲染执行过程面板并启动计时。
2. 过程事件到达后，直接追加到已展开的面板内容中。
3. 在最终输出尚未提交前，不显示最终答案正文。
4. 最终输出提交后，面板从默认展开切换为折叠，最终答案紧随其后显示。
5. 如果用户已经手动设置展开状态，自动状态切换不覆盖用户选择。
6. 持久化回放使用已保存的总用时和步骤数据，默认以折叠状态显示在最终答案之前。

## 测试

新增或调整前端回归测试，覆盖：

- 没有工具事件的流式回合仍要求显示执行面板和计时状态；
- 多个技术操作只形成一个可折叠执行面板；
- 展开后直接得到真实步骤行，不存在第二层 disclosure；
- 最终输出出现时面板折叠但不消失，最终答案位于其后；
- 完成摘要使用可见步骤数并排除缓存步骤；
- 手动展开状态不被自动折叠覆盖。

验证范围包括聚焦前端测试、TypeScript 类型检查、前端单元测试和完整 Agent 重构门禁。真实页面验证只观察执行面板生命周期，不发送新的生产 Agent 请求。

## 非目标

- 不恢复“已操作”“正在操作”“准备操作”等旧文案。
- 不恢复工具行自己的展开状态。
- 不改变顶部任务进度胶囊的显示规则。
- 不改变 Agent 事件协议、持久化格式或后端执行状态机。
