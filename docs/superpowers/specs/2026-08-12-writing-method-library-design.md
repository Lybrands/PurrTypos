# 写作方法库设计规格

范围：写作方法、写作方案、作品绑定、Writing Agent 运行时、原作提炼接入，以及旧风格基调退役

> 实施注意：本文第 3.4 节的内部 catalog 重命名、第 8.4/11 节的独立运行收据表和六表模型、以及第 16 节的旧实施顺序已经被 2026-08-27 当前计划修正。其余已确认的产品行为继续有效；发生冲突时以当前计划为准。

## 1. 背景与目标

现有“风格基调”只服务于单本小说，字段固定，无法自然承载一部原作中可复用的叙事风格和专项技法。小说续写能力又需要把原作中的写法蒸馏为持久、可审核、可组合的创作资产。

本设计用统一的“写作方法库”取代旧风格基调，实现：

1. 内置若干可直接使用的写作方法与写作方案；
2. 用户可通过引导表单或空白 Markdown 创建完全自定义的方法；
3. 多个方法可组成不可拆分的写作方案；
4. 作品绑定准确的已发布版本，不自动跟随后续修改；
5. Writing Agent 常驻主风格，并按当前任务选用专项方法；
6. 用户可用 `/` 控制当前请求使用或排除哪些已绑定方法；
7. 原作分析可生成一组候选方法及候选方案，经审核后发布；
8. 产品业务保持在 Writing 组合边界，通用 Agent Core 不感知方法库。

## 2. 明确不做

- 不建设在线市场、第三方插件协议或文件目录式方法安装机制。
- 不允许方法正文声明或获得工具权限。
- 不允许 Agent 自行绑定、升级、解绑方法或调整作品优先级。
- 不在普通写作过程中主动弹出推荐。
- 不让作品或方案引用未发布草稿。
- 不让作品随方法或方案的新版本自动变化。
- 不把原作证据全文复制进方法正文。
- 不迁移旧风格基调数据。
- 首版不自动清理已发布历史版本。

## 3. 术语与边界

### 3.1 写作方法

一个可复用的创作指导文档，类型为：

- `primary`：主风格，描述整体叙事声音、视角、语言密度和节奏；
- `technique`：专项技法，描述对白、悬念、战斗、情绪推进等局部写法。

每个方法包含独立管理元数据和一篇自由 Markdown 正文。正文不要求固定标题或章节，可以从空白开始，也可以由引导创建生成后完全重写。

### 3.2 写作方案

一组有顺序的方法版本组合。方案是快速复用的稳定预设：

- 作品只能整体绑定或解除一个方案；
- 不能在作品中删除、替换方案内部的某个方法；
- 用户需要不同组合时，应从空白新建方案，或复制现有方案后修改；
- 一本作品可以同时绑定多个包含主风格的方案。

### 3.3 作品方法栈

某本作品绑定的方案版本和独立方法版本构成有序方法栈。用户可以调整这些顶层绑定的优先级。优先级只决定上下文中规则的解释顺序，不尝试解析自由 Markdown 后逐条合并规则。

### 3.4 Agent 工具定义

现有 `backend/skills/*/SKILL.md` 是 Agent 工具的模型可见声明，解决“Agent 能做什么”，不属于本设计的创作方法。

实现时将现有 `WritingSkillCatalog` 重命名为 `WritingToolDefinitionCatalog`。新的写作方法系统不复用工具 `SKILL.md` 文件格式，也不向通用工具目录注册用户正文。

## 4. 产品结构

### 4.1 全局写作方法库

写作方法库是用户级全局模块，不属于任何一本小说。主导航下只设置两个主要页面：

- 写作方法；
- 写作方案。

列表支持按来源筛选：内置、我的、从原作提炼。详情区域使用常规 Markdown 文档视图，辅助显示版本、类型、标签、来源和引用状态；默认不暴露内部 JSON。

### 4.2 创建写作方法

提供两个平级入口：

1. **引导创建**：用户填写目标、适用场景、创作要求等，宿主按固定模板生成一份草稿；
2. **空白创建**：直接打开空白 Markdown 编辑器。

两条路径最终进入同一个自由编辑器。编辑自动保存草稿，只有用户主动点击“发布”才产生不可变版本。

发布只做最低内容校验：

- 正文非空；
- 正文未超过产品设定的存储和上下文上限；
- 内容可以正常持久化。

不强制任何 Markdown 章节或模板结构。

### 4.3 创建写作方案

方案草稿从已发布的方法版本中选择成员并排序。发布前展示即将冻结的方法版本清单。

如果方案草稿包含尚未发布的新方法，发布界面统一预览这些草稿；用户一次确认后，在同一事务中先发布方法版本，再发布方案版本。任何一步失败都不产生部分发布结果。

### 4.4 内置内容

- 内置方法和方案不可直接修改或删除；
- 用户可以停用内置内容；
- 用户可以复制内置方法或方案，复制品是独立的自定义对象；
- 应用升级可以增加内置版本，但不得改变作品已经绑定的版本。

### 4.5 作品内入口

小说工作台增加“写作方法”入口，用于：

- 查看当前方法栈；
- 添加已发布的方法或完整方案；
- 调整顶层绑定的整体优先级；
- 解除绑定；
- 查看可升级版本及差异，并手动升级；
- 按需请求 Agent 推荐。

作品需要专属写法时，创建一个普通自定义方法并将其排在方法栈前面，不再设置特殊的作品级风格对象。

## 5. 草稿、发布与版本

### 5.1 方法版本

- 日常编辑只覆盖当前草稿，不产生历史版本；
- 发布时生成不可变版本 `v1`、`v2` 等；
- 修改已发布方法时，编辑的是下一版草稿；
- 作品和方案只引用准确的方法版本 ID；
- 发布新版不改变已有作品或方案。

### 5.2 方案版本

- 方案草稿保存当前有序成员清单；
- 发布时冻结方案内容及每个成员的准确方法版本 ID；
- 方法发布新版不会改变旧方案版本；
- 若要采用新版方法，必须修改并重新发布方案。

### 5.3 作品绑定

- 作品绑定准确的方案版本或方法版本；
- 绑定后不自动变化；
- 新版出现时只显示升级提示和差异；
- 用户明确确认后才替换绑定版本；
- 方案在作品中始终保持原子性。

## 6. 删除、归档与引用完整性

- 内置方法和方案不可物理删除；
- 没有被任何作品、方案或运行记录引用的自定义内容可以彻底删除；
- 已被引用的版本不可物理删除；
- 被引用对象只能归档，从默认列表隐藏，但历史引用继续可读；
- 删除未被作品引用的方案，不影响方法本身；
- 解除作品绑定只删除绑定关系，不删除方法、方案或历史运行记录；
- 首版不做自动版本清理，因为只有人工发布才会产生版本。

## 7. 组合、优先级与冲突

作品可以同时绑定：

- 多个完整写作方案；
- 多个独立写作方法；
- 多个包含主风格方法的方案。

宿主按用户设置的顶层优先级展开方法栈。规则如下：

1. 同一个方法版本通过多个路径出现时只生效一次；
2. 同一个方法的不同版本同时出现时视为硬冲突，发送请求前要求用户选择；
3. 方案内部顺序由方案版本冻结，作品不能调整；
4. 作品只能调整方案与独立方法这些顶层项的顺序；
5. 自由 Markdown 不做逐条机器解析，冲突提示以版本身份和明显元数据冲突为主；
6. 系统安全规则、工具权限和宿主作用域始终高于全部创作方法，不参与用户排序。

## 8. Writing Agent 运行时

### 8.1 上下文组装

每次写作请求由 Writing 产品层执行：

```text
作品绑定
→ 展开方案并校验方法版本
→ 去重和版本冲突检查
→ 合并本轮强制使用与排除
→ 注入主风格方法
→ 按任务选择少量专项方法
→ 执行 Writing Agent
→ 保存实际使用记录
```

通用 Agent Core 只接收已组装的受限上下文，不查询方法库业务表，也不理解方法、方案或作品绑定。

### 8.2 两级激活

- 主风格方法在每次写作中常驻；
- 专项方法先以名称、简介、标签的轻量目录参与任务匹配；
- Agent 只读取与当前任务相关的少量专项方法正文；
- 用户明确要求的方法本轮强制激活；
- 用户明确排除的方法本轮不可被自动选择。

方案在绑定层保持完整，不等于运行时必须把全部成员正文注入每个请求。

### 8.3 `/` 本轮选择器

在 AI 输入框键入 `/` 打开“选择本次写法”：

- 只列出当前作品已经绑定的方法；
- 按所属方案和独立方法分组；
- 支持多选本轮强制使用；
- 支持标记本轮排除；
- 选择方案内单个方法只影响本次请求，不修改或拆分方案；
- 未绑定的方法不能临时使用，必须先从方法库绑定到作品。

### 8.4 运行记录

每次 Agent 运行保存实际使用的方法版本清单，包括：

- 因主风格常驻而使用；
- Agent 自动选择；
- 用户通过 `/` 强制使用；
- 用户本轮排除。

结果界面展示本次实际使用的方法，历史请求可以还原同一组准确版本。

## 9. 按需推荐

推荐只在用户点击“推荐写作方法”或明确向 Agent 提问时触发，普通写作过程中不主动打断。

推荐流程：

1. 读取作品题材、当前任务、已有绑定和用户目标；
2. 根据方法名称、简介、类型、分类、标签、适用题材和来源筛选少量候选；
3. Agent 读取候选正文；
4. 给出方法或完整方案建议、理由和冲突提示；
5. 用户确认后才绑定准确版本。

首版使用普通元数据查询，不引入向量数据库。方法数量和检索质量证明需要后，再增加语义检索。

## 10. 从原作提炼

来源分析把写法结果拆成一组候选创作资产，而不是一篇超长综合文档：

- 一个或多个主风格候选方法；
- 两至五个专项候选方法；
- 一个引用这些候选方法的候选方案。

候选结果进入审核页，用户可以逐项修改、删除或保留。最终一次确认后，原子发布保留的方法和方案。

方法正文只保存蒸馏后的写作指导。证据、原文片段、来源修订和分析覆盖范围继续保存在原作分析档案中；方法只保存稳定的来源引用，避免重复数据和版权材料扩散。

发布后不自动绑定续写作品。用户在续写创建或作品方法入口中明确选择后才建立绑定。

## 11. 数据模型

首版使用六张核心表。

### `writing_methods`

保存方法身份及可变草稿：名称、简介、类型、分类、标签、适用题材、草稿 Markdown、草稿修订号、来源类型、来源引用、内置标记、状态、当前已发布版本和时间戳。

### `writing_method_revisions`

保存不可变已发布版本：方法 ID、版本号、Markdown 正文、元数据快照、内容摘要和发布时间。方法 ID 与版本号唯一。

### `writing_schemes`

保存方案身份及可变草稿：名称、简介、有序成员草稿、草稿修订号、来源、内置标记、状态、当前已发布版本和时间戳。

### `writing_scheme_revisions`

保存不可变方案版本：方案 ID、版本号、准确方法版本 ID 的有序清单、元数据快照、内容摘要和发布时间。

方案成员数量有限，首版直接保存有序 JSON 快照，不另建成员关系表。

### `book_writing_method_bindings`

保存作品顶层方法栈：作品 ID、绑定类型、方案版本 ID 或方法版本 ID、优先级、来源和时间戳。必须保证一条绑定只指向一种版本类型。

### `writing_method_run_receipts`

保存一次 Agent 运行对方法版本的实际使用记录：运行 ID、作品 ID、方法版本 ID、激活原因、所属方案版本、本轮状态和时间戳。

## 12. 应用服务边界

### 方法库服务

负责创建、复制、编辑草稿、发布、归档和删除。发布方法、发布方案以及原作候选批量发布都通过原子事务完成。

### 作品方法解析器

负责展开方案、去重、校验版本冲突、合并 `/` 本轮选择、实施上下文预算并产生可记录的激活结果。

### 按需推荐服务

负责筛选候选和形成建议，不拥有作品绑定写权限。用户确认绑定仍由明确的宿主命令完成。

### 原作提炼适配器

负责把已验证的来源分析结果转换为候选方法草稿及候选方案，不拥有发布权限。

## 13. 并发、失败与恢复

- 草稿更新携带草稿修订号；版本不匹配返回冲突，不能覆盖另一窗口的新内容；
- 发布操作使用数据库事务；失败时不产生半个方法版本或不完整方案；
- 绑定缺失或损坏版本时直接报错，不能静默跳过；
- 方法栈出现同方法多版本冲突时阻止请求并提示用户解决；
- 上下文超限时先减少自动选择的专项方法，不截断某篇方法正文；
- 常驻主风格本身超限时明确提示用户调整绑定或正文；
- 原作分析中断可以保留候选草稿与任务状态，但不能发布半成品；
- 已开始的 Agent 运行使用启动时解析出的准确版本，不受并发发布新版影响。

## 14. 旧风格基调退役

这是明确的破坏性迁移：

- 删除现有风格基调界面及入口；
- 删除风格基调 API、Schema、CRUD 和 `getBookStyle` 工具；
- 删除 `book_style` 表及其全部数据；
- 不迁移、不转换、不导出、不保留兼容读取；
- 清除 Writing Prompt、Screenplay 来源读取、编辑器续写等所有风格基调注入路径；
- 数据库备份仍按数据库文件整体保留历史状态，但升级后的运行时代码不再读取旧结构。

实施前必须再次列出准确删除目标并确认现有调用点，避免遗漏隐式注入路径。

## 15. 验证门禁

必须覆盖以下行为：

1. 自动保存不产生版本，发布才产生版本；
2. 已绑定作品不随方法或方案新版变化；
3. 方案在作品中保持原子绑定；
4. 多方案优先级、重复版本去重和多版本冲突正确；
5. `/` 不能选择未绑定的方法；
6. 内置内容只能复制，不能修改或删除；
7. 被引用版本不能物理删除；
8. 每次运行可还原实际使用的方法版本；
9. 原作证据不复制进方法正文；
10. 通用 Agent Core 不依赖写作方法业务；
11. 发布和批量发布失败时无部分持久化；
12. 草稿并发更新不会静默覆盖；
13. 删除旧风格基调后不存在残留注入路径；
14. Web 与 Electron 使用相同服务/API 行为。

## 16. 实施顺序与续写能力关系

1. 建立写作方法库与版本模型，并彻底删除旧风格基调；
2. 实现写作方案、作品绑定、优先级和版本冻结；
3. 接入 Writing Agent 方法解析、运行记录及 `/` 选择器；
4. 增加内置方法、按需推荐和复制自定义；
5. 在原作分析管线中增加候选方法与候选方案产物；
6. 将候选审核发布接入续写创建和作品方法入口。

写作方法库基础能力先于“原作风格提炼”，但不阻塞原作导入、章节解析、事实分析和正史快照等续写基础工作。两个方向通过稳定的来源分析引用和候选草稿接口衔接。

## 17. 完成定义

只有以下闭环真实可用，才视为写作方法库首版完成：

```text
创建或复制写作方法
→ 编辑草稿且不制造版本噪声
→ 主动发布不可变版本
→ 组合并发布写作方案
→ 作品绑定准确版本并排序
→ Writing Agent 常驻主风格、按任务选专项方法
→ 用户用 / 控制本轮选择
→ 运行记录可还原实际使用版本
→ 新版本不会静默改变已有作品
```

原作提炼扩展的完成闭环为：

```text
来源分析完成
→ 生成一组候选方法和候选方案
→ 用户审核、修改和删选
→ 原子发布
→ 用户明确绑定到续写作品
→ 原作证据仍只存在于来源分析档案
```
