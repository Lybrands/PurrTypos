# 剧本审阅入口与弹窗设计

## 问题与根因

审阅裁决是阶段性操作，但当前实现把 `ReviewAdjudicationPanel` 常驻在中央主内容列，并与 Agent 对话工作台上下分割。即使面板宽度正确，它仍持续占用对话区域的高度，破坏了页面的主次关系：用户的大多数时间在与 Agent 对话，只有处理审阅意见或确认定稿时才需要进入审阅界面。

因此问题不是分割比例不合适，而是审阅裁决被放在了错误的信息层级。

## 方案比较

1. **CURRENT TASK 入口 + 大弹窗（采用）**：右侧当前任务卡负责告诉用户当前要做什么，并提供“处理审阅意见”“查看审阅决定”或“确认定稿”的入口；点击后打开大弹窗完成审阅裁决。入口贴合任务语义，对话区始终保持完整。
2. **项目文档内嵌裁决**：可以复用“审阅修订”分类，但会把不可变审阅报告和可变用户裁决混在同一文档阅读器中，容易让用户误以为正在编辑报告本身。
3. **右侧抽屉**：不覆盖主界面，但长审阅意见在窄抽屉中仍然拥挤，也会在使用期间压缩或遮挡对话区。

## 确认设计

- `.screenplay-agent-studio` 恢复为中央 `agent` Grid Area 的唯一常驻内容，占满原有高度。
- 当项目存在当前审阅报告时，`CURRENT TASK` 卡显示一个审阅入口：
  - `adjudicating`：`处理审阅意见（N）`
  - `readyToRevise`：保留主操作“开始修订”，同时提供次操作“查看审阅决定”
  - `readyToFinalize`：`确认定稿`
  - `completed`：`查看定稿记录`
- 审阅入口打开宽屏大弹窗。弹窗内复用现有 `ReviewAdjudicationPanel` 的统计、批量处理、逐项处理、开始修订和确认定稿能力。
- 弹窗外壳不滚动；超长内容只让意见列表滚动，标题、统计、工具栏和底部主操作保持可见。
- 项目文档继续只承担当前/历史审阅报告阅读，不承载用户裁决状态，以免混淆不可变报告与可变流程状态。
- 项目切换或当前审阅报告消失时自动关闭弹窗；请求执行中禁止关闭造成误操作。

## 验收标准

- 弹窗关闭时，中央对话工作台恢复完整高度，页面不再出现常驻审阅面板。
- `CURRENT TASK` 卡始终提供与当前审阅阶段匹配的入口文案。
- 点击入口后，审阅面板以可用宽度打开；八条长意见只在意见列表内滚动。
- `readyToRevise` 阶段仍可直接开始修订，也能回看裁决记录。
- 已归档或已完成项目可查看记录，但不能修改裁决。
- TypeScript、前端单测、Agent 重构门禁和宽/窄屏视觉回归通过。
