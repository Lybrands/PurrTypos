# 全局弹出层层级协议设计

## 背景

剧本审阅弹窗中的审阅项状态菜单虽然已经渲染到 Portal，但菜单所在的 `Positioner` 没有获得有效层级；实际的 `z-index` 写在内部 `Popup` 上。由于 `Positioner` 自身因定位变换建立了层叠上下文，内部 `Popup` 无法越过外部 Dialog 的层叠上下文，最终表现为菜单存在却被弹窗内容盖住，点击落到下面的审阅文本上。

这不是审阅状态接口或按钮状态机失效，而是共享弹出层组件缺少统一的层级协议。当前代码还散落着 `1000`、`1040`、`1100`、`1200`、`1300`、`1400`、`9999` 等数值，不同组件对 `Portal`、`Positioner`、`Popup`、遮罩和面板的层叠责任也不一致。继续为单个菜单增加专用 class 只会把相同问题转移到 Select、Popover、Tooltip 等组件。

## 目标

1. 在 `1000–1999` 内建立一套可审计的全局弹出层语义协议。
2. 让同类组件共享权重，不为每个实例发明递增数字。
3. 把层级施加到真正建立层叠上下文的节点，而不是仅施加到视觉内容节点。
4. 所有公共弹出层组件提供一致的可选 `zIndex` 覆盖入口。
5. 业务代码默认只选择组件和语义，不直接编排原始层级数值。
6. 恢复审阅项单项处理和批量处理等被遮挡交互，并建立回归门禁。

## 非目标

- 不修改审阅项的业务状态、后端裁决接口或批量处理语义。
- 不引入运行时层级管理器、自动递增栈或新的第三方依赖。
- 不用 `1011`、`1012` 表示组件内部的细小层级。组件内部在独立层叠上下文中只使用 `0–9`。
- 不承诺任意第三方页面都能遵守本协议；公共组件的显式 `zIndex` 参数用于必要的边界覆盖。

## 设计原则

### 全局层级与局部层级分离

`1000–1999` 只用于跨组件、跨 Portal 或 fixed 浮层的全局竞争。组件内部如果已经拥有独立层叠上下文，装饰、内容、悬浮按钮等只使用 `0–9`。

CSS 的 `z-index` 不会做父子加法。父层级为 `1200`、子层级为 `2`，不等于全局 `1202`；子元素只能在父级所属的层叠上下文内排序。因此全局权重必须写在负责与其他浮层竞争的根节点上。

### 语义默认值优先，显式覆盖作为逃生口

每类组件从统一 CSS 自定义属性读取默认层级。绝大多数业务调用不传 `zIndex`。只有确定存在特殊嵌套或宿主环境冲突时，调用方才通过公共组件的 `zIndex` 参数覆盖。

覆盖参数不会直接散落为业务侧 `style={{ zIndex }}`，而由组件负责写到正确节点。这样既保留强制覆盖能力，也不破坏公共组件对层叠结构的所有权。

## 全局层级表

| 权重 | 语义 | 组件或场景 |
| ---: | --- | --- |
| 1000 | 非阻塞浮层 | 全局搜索、辅助浮窗、编辑器浮动工具 |
| 1050 | 开发诊断 | `AiDevInspector` 等开发期检查器 |
| 1100 | Drawer 遮罩 | 抽屉背景遮罩 |
| 1110 | Drawer 前景 | Drawer 面板与交互内容 |
| 1200 | Modal 遮罩 | Dialog、Modal、Confirm 的背景遮罩 |
| 1210 | Modal 前景 | Dialog、Modal、Confirm、Command Palette |
| 1220 | 操作型弹层 | Dropdown、ContextMenu、Popover、Popconfirm、Select、MultiSelect |
| 1230 | 说明型弹层 | Tooltip |
| 1300 | 全局反馈 | Toast region |

相同语义的组件允许使用相同权重。同层实例依靠 Base UI 的嵌套管理和稳定的 DOM 顺序排序，不再创建 `1211`、`1212` 之类的实例编号。当前不使用 `1300` 以上的层级，但 `1000–1999` 仍作为完整保留区间。

## 层级注册表

新增单一的全局层级样式入口，例如 `src/styles/layers.scss`，由应用根样式只导入一次。该文件声明语义化 CSS 自定义属性：

```scss
:root {
  --purr-z-floating: 1000;
  --purr-z-diagnostics: 1050;
  --purr-z-drawer-backdrop: 1100;
  --purr-z-drawer: 1110;
  --purr-z-modal-backdrop: 1200;
  --purr-z-modal: 1210;
  --purr-z-popup: 1220;
  --purr-z-tooltip: 1230;
  --purr-z-toast: 1300;
}
```

具体命名可在实施时与现有样式约定对齐，但层级值、语义和单一注册表原则不变。组件样式只能引用这些变量或使用局部 `0–9`，不能复制全局数字。

## 公共组件契约

### 锚定型弹层

以下组件公开可选参数 `zIndex?: number`：

- Dropdown
- ContextMenu
- Popover
- Popconfirm
- Select
- MultiSelect
- Tooltip

未传参数时，操作型弹层使用 `--purr-z-popup`，Tooltip 使用 `--purr-z-tooltip`。传入参数时，组件把最终值应用到 Base UI 的 `Positioner`，因为它才是参与全局层叠竞争的节点；内部 `Popup` 只负责视觉样式和局部层级。

ContextMenu 复用 Dropdown 的契约，Popconfirm 复用 Popover 的契约，不建立第二套覆盖逻辑。

### 阻塞型容器

Modal、Dialog、Confirm 和 Drawer 同样公开 `zIndex?: number`。该参数表示前景面板或 viewport 的最终层级：

- Modal/Dialog/Confirm 默认前景为 `1210`，遮罩为 `1200`。
- Drawer 默认前景为 `1110`，遮罩为 `1100`。
- 显式传入 `zIndex` 时，前景使用该值，遮罩自动使用 `zIndex - 10`。

Confirm 通过 Dialog 继承同一实现，不复制计算规则。Command Palette 使用 Modal 前景语义；若它仍是专用实现，也必须引用相同注册表变量。

### Toast

Toast 只允许在全局 Provider 或 Region 级别配置 `zIndex?: number`。单条消息不能自行抢占全局层级。实施时同时修正现有 Toast 组件 class 与样式选择器命名不一致的问题，确保默认层级确实命中实际 region。

### 覆盖值约束

公共契约约定显式值位于 `1000–1999`。由于 TypeScript 无法可靠表达任意数字的闭区间，组件在开发环境对越界值发出可定位的警告；为保持“强制覆盖”的语义，不静默裁剪或替换调用方传入的值。生产环境仍应用原值。

业务侧只能通过组件参数覆盖，不直接向 Portal 子节点传入裸 `z-index` 样式。公共组件实现是把参数转换为节点样式的唯一边界。

## 渲染与数据流

1. 业务组件渲染公共弹出层，可省略 `zIndex` 或显式传入覆盖值。
2. 公共组件计算 `effectiveZIndex = zIndex ?? semanticDefault`。
3. 锚定型弹层把有效值交给 `Positioner`；阻塞型容器把前景值交给 viewport，把前景减 10 后交给 backdrop。
4. Portal 把节点挂载到 document 层，但组件根节点携带正确的层级，因此不依赖原业务 DOM 的祖先层级。
5. 用户点击命中视觉上最前面的交互元素，审阅项按钮继续调用现有单项或批量裁决流程。

该流程只改变表现层命中关系，不新增业务状态，也不改变审阅请求的数据结构。

## 兼容性与错误处理

- `zIndex` 全部为可选参数，未修改的现有调用自动获得语义默认值。
- `undefined` 使用默认层级；不把 `0` 当成缺省值。
- 非有限数字、非整数或 `1000–1999` 之外的值在开发环境给出带组件名的警告，便于定位调用点；组件仍应用显式值，不制造环境间行为差异。
- 遮罩层计算只存在于公共 Dialog/Drawer 实现中，业务方无需同时维护两个数字。
- 如果 Base UI 某个 primitive 不接受 `style`，应在同一公共组件内增加稳定的 Positioner/Viewport class 或 CSS 自定义属性承载层级，不能把解决责任推回业务页面。

## 迁移策略

1. 建立层级注册表并接入应用根样式。
2. 为全部公共弹出层补齐 `zIndex` 参数和真实层叠根节点 class/style。
3. 迁移 Dialog、Drawer、Confirm、Command Palette、Toast、AiDevInspector 和非阻塞浮层到语义变量。
4. 全量盘点现有 `z-index`：组件内部确属局部排序的值收敛到 `0–9`；参与全局竞争的值改为注册表变量。
5. 修正 Toast class 命名不一致，避免层级样式处于未命中状态。
6. 最后启用静态门禁，防止迁移过程中被历史值阻塞，也避免迁移后再次散落数字。

迁移时不能机械地把所有数值降低。每个现有值必须先判断所属节点是否拥有独立层叠上下文；没有隔离的局部 UI 要么建立明确上下文，要么归入合适的全局语义。

## 静态门禁

增加轻量检查脚本并接入现有前端检查流程：

- 层级注册表之外，SCSS/CSS 中只允许 `z-index: 0–9`、语义变量和非数字关键字。
- TS/TSX 业务代码中禁止新增裸 `style={{ zIndex: ... }}`；公共弹出层实现是允许的适配边界。
- 禁止重新引入 `9999` 等越权值。
- 检查脚本只负责静态协议，不尝试模拟浏览器层叠算法。

## 测试与验收

### 组件测试

- 各公共弹出层在未传参数时命中对应语义默认值。
- 显式 `zIndex` 写在 Positioner、viewport 或 region 等真实层叠根节点上，而非仅写在 Popup 内容上。
- Dialog/Drawer 显式前景层级与自动减 10 的遮罩层级一致。
- `zIndex={0}` 不会被错误替换为默认值。
- 开发环境对非法或越界值报警，显式值仍被应用。
- ContextMenu、Popconfirm、Confirm 分别继承其基础组件契约。

### 浏览器交互验收

- 在 Modal 内依次打开 Dropdown、Select、MultiSelect、Popover、Popconfirm 和 Tooltip，视觉显示与点击命中一致。
- 在 Drawer 内重复关键弹层组合。
- 审阅弹窗中的单项状态按钮可展开并完成状态更新。
- 批量处理按钮可展开并触发既有批量流程。
- 使用测试覆盖值（例如 `1250`）时，浏览器命中测试确认覆盖生效。
- AiDevInspector 位于业务 Modal 下方；Toast 位于普通业务弹层上方。
- 同层多个弹窗或弹层按照嵌套关系和 DOM 顺序稳定显示。

### 回归门禁

- 前端类型检查通过。
- 相关组件测试和审阅交互测试通过。
- 层级静态检查通过。
- 浏览器验收使用只读数据或数据库副本；若测试涉及状态更新，则使用专用测试数据，不修改用户现有审阅结果。

## 风险与控制

- **风险：层级写在错误节点。** 组件测试直接断言 Positioner/viewport/region 的最终样式，浏览器测试再以实际点击命中验证。
- **风险：相同权重导致顺序不稳定。** 同层只分配给语义相同的组件，依靠 Base UI 嵌套管理和稳定 DOM 顺序；跨语义组件不共享同一权重。
- **风险：业务方滥用覆盖参数。** 默认层级覆盖常规场景，越界值开发警告，静态门禁禁止绕过公共 API。
- **风险：迁移旧值破坏局部 UI。** 逐项判断层叠上下文并进行视觉回归，不做全局搜索替换式降级。

## 决策结论

采用集中式 CSS 语义变量加公共组件 `zIndex` 逃生口的方案。不引入动态 LayerProvider 或自动递增层级管理器。该方案用最少的新机制统一现有 Base UI 包装层的责任，同时保留处理宿主环境和特殊嵌套的能力。
