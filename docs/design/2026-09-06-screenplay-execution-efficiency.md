## 取材合同

`getScreenplaySceneContext` 仍由模型显式调用，一次返回宿主锁定的当前场景、前场依赖、创作简报、原作分析目录及本集分集结构。分集结构只读取锁定 Revision 的当前 episode，不返回整个系列。原文仍按需通过来源工具读取。

分析目录提供 `readRequests`，包含合法 role、revisionId、structured 表示和 sectionKeys。sectionKeys 指文档字段键，不是章节名、章节 ID 或模型自拟分类。无效键仍拒绝，但同一错误响应提供当前已授权文档的合法读取参数，避免为了修正参数再次查询目录。一次读取可合并同文档多个相关键；不得重复取已经收到的完整材料。

这两个读取工具的缓存合同升为 4，避免旧缓存缺少新增字段；其他工具保留原缓存身份。依然记录真实工具事件，不从缓存自动填充初始模型输入。

## 收尾合同

- 集标题与连续性摘要使用“读取本集场景 → 最终 JSON → 宿主原子校验与保存”。元信息模型只有依赖读取权限，不再调用候选写入工具，也不再追加写入后的确认轮。正常单批读取流程由 3 次模型调用减少为 2 次；多于 12 个依赖时仍按已有读取上限分批。
- JSON 的字段、集数、非空标题与摘要使用同一领域校验器。错误结果走 Core 有限修正；候选仍在 Run DONE 的事务中校验读取凭据、规范化并正式保存。私有候选不会因此公开。
- 检查点只有在明确的 required 业务单元全部完成、剩余集数与小节清单为空、有产物收据、没有失败或约束变化时直接返回 unchanged。最终公开回复不算尚未完成的创作业务。缺失状态、未完成业务、失败或变化仍调用规划模型。
- 直接 unchanged 同样经过原有检查点预约、持久化与应用流程，不绕过 lease、幂等、取消或 Root 计划收口。
