# 来源小说与续写工作台的完整继承

日期：2026-09-08。状态：C1–C5 已实施并完成分层验收；累计门禁、Web 构建和短样本真实链路均通过，长篇文风质量未获证明。以下实施前缺口保留作对照，实际完成情况见末尾记录。

## 目标与范围

后续已确认改造：[来源分析产物与证据引用](2026-09-08-source-analysis-materials-plan.md)。分析将按创作资料组织、用派生续写起点替代概览正史、证据改为集中保存与引用。该后续改造尚未实施，不覆盖下方既有验收记录的时间边界。

上传小说进入来源库，经分析得到可追溯的故事资料与写作技法。来源保存分析及技法的关联。从该来源创建续写时，一次性初始化历史章节、人物背景等创作资料及默认技法，进入现有小说工作台继续创作。

此设定覆盖旧计划中“创建续写不默认选择来源技法”的规则。普通原创作品仍默认仅手动指定且无默认技法；生成结束本身不向任何既有小说授予权限。只有创建续写时，才为目标作品建立明确的默认选择与访问权限。

## 已确认的用户需求

1. 分析生成的技法与对应小说来源关联，可从来源查看和管理。
2. 续写工作台的章节目录显示原作历史章节，正文只读，不可通过编辑、删除、移动或 AI 修改覆盖。
3. 来源技法在续写中默认带上，输入器呈现已选状态，不要求用户每轮重复添加。
4. 分析产生的人物、故事背景及其他有依据的创作材料进入续写作品的相应资料入口，供用户和现有创作 Agent 使用。
5. 原创与续写复用工作台和 Writing Agent。续写额外拥有历史正文、继承资料和来源技法；不建立另一套编辑器或模型执行框架。

## 实施默认与业务边界

以下为落实需求的实施选择，后续变更需同步契约和测试。

### 来源、分析与技法

- 关联保存 sourceWorkId、sourceRevisionId、analysisId、分析覆盖范围和准确 techniqueId/versionId。生成候选立即具有来源归属，但候选、材料不足与可使用版本明确区分。
- 创建续写默认选用本次所选正式分析对应的可用技法版本，不使用全库搜索结果，也不混用其他分析的技法。不把文件 owner 中的任务 ID 当成唯一业务关联。
- 同一来源多次分析保留历史关联；来源当前展示可用结果，已有续写固定创建时的版本，后续重新分析不静默覆盖。
- 创建页展示要继承的技法和资料摘要；创建操作包含授权目标续写使用这些准确版本。仍为候选的技法先完成现有确认／保存流程；无可用技法时明确显示缺项，允许用户明确选择无技法创建，不能伪装为已带入。
- 删除或撤销受引用资源沿用明确的引用处理流程，不能令已有续写默认配置悄悄悬空。

### 历史章节目录与正文

- 默认沿用当前章节末尾分叉规则；继承冻结来源版本中分叉点及之前的章节。若从作品末尾续写，即显示全部历史章节。
- 同一工作台目录包含原作历史章节和后续可编辑章节；保留已有卷层级与顺序。来源没有卷信息时不编造卷。章节项明确标识只读。
- 历史章节采用独立来源身份，不伪装成可编辑 chapterId；选中后打开只读正文。编辑器、快捷键、菜单、拖拽、保存接口和 AI 修改工具都按节点身份执行限制，不能只禁用按钮。
- 提供可分页的历史章节目录与只读正文读取；Agent 能获得合法章节 ID、标题和顺序，再调用现有读取工具。只有正文读取而没有发现目录不算完整接入。
- 后续章节创建、编辑和编号与历史顺序衔接。导出明确区分完整作品与仅续写部分，避免默认遗漏历史内容或重复拼接。
- 保证冻结历史在原来源更新、删除和备份恢复后仍能读取；使用受引用保留或续写独立冻结副本，实施时按现有来源存储选择统一方案。不能只保留资料快照而允许正文丢失。

### 技法默认选择与实际使用

- 模式仍为 manual。作品保存来源技法的固定版本默认选择，新会话继承默认值；本轮实际选择在输入器可见，用户可以取消、替换或补充。
- 会话保留用户对默认技法的选择状态；发送后只清空临时添加的本轮内容，不清空持续默认项。明确取消后不能下一轮重新偷偷补回。作品默认配置修改仅初始化后续新会话，已有会话自主保留配置。
- 后端区分未指定配置、明确空选择和恢复历史 Run，不能用空数组同时表示“用默认”与“全部取消”。入队冻结有效选择、版本及授权，恢复不重新取默认值。
- 默认选中不等于自动搜索：只授权来源关联的准确版本，不扩大为全库授权。默认选择必须进入现有运行准入、读取与证据记录。
- 写作从 SKILL.md 入口开始；辅助文件按需读取。验证的是模型实际收到入口，而非仅 UI 已勾选；不额外加载整包。

### 资料继承

- 初次创建进行一次快照初始化，不建立双向实时同步。续写编辑不会回写来源，重新分析不会覆盖续写已有修改。
- 人物身份、人物当前状态、关系、世界规则和背景分别映射到现有角色、设定及背景资料；事件、时间线、未决情节、伏笔按现有对应领域保存。原文证据与出处保留关联，不伪造模型未分析出的字段。
- 原作截至分叉点的事实作为不可改写的继承基线；工作台相应资料入口能查看该基线及本书后续发展。不得只显示一个 JSON 正史面板，也不得把基线与续写发展混成同一可随意覆盖的记录。
- 当前状态要按时间理解：原作中人物在某时受伤不代表续写不能康复。保留历史事实和后续变化，不能用“正史永远优先”阻止合理剧情发展。
- 提取覆盖不等于资料完整：缺失字段保持未定，冲突不强行合并，实体映射用稳定来源标识而不是只按姓名。涉及分叉点之后的事实、背景说明或隐含剧透不得继承。
- 不把事实压缩成独立平行的 Story Memory 再重复注入。复用当前共享 Markdown 资料及既有上下文入口，明确每种资料的正式存储位置、映射 ID 和读取权限。

### 生成技法的内容目标

- 技法供创作 Agent 使用，抽象出有来源依据的语言、叙述、节奏与铺垫方式，服务于延续文风。
- 技法不依赖事先读过原作，但允许 Agent 为场景衔接、细节和文风校准按需读取历史章节。技法不是历史正文的替代品，不包含整套故事事实副本。
- 部分篇章分析只能说明该范围支持的写法；不能把局部特点声称为整部作品的统一文风。默认绑定不能证明风格一致，需另用实际续写结果验收。

## 实施顺序与交付

1. **C1 继承契约与快照**：建立来源分析—技法版本关系及继承清单；创建请求绑定清单摘要与 operationId。清单包括章节范围、资料映射及默认技法；执行前复核。SQLite 与文件不共享事务，需预备文件、可恢复提交和幂等恢复，完成前作品不得以已就绪状态进入工作台。
2. **C2 历史章节**：目录 API、节点类型、只读阅读、Agent 目录发现与原文工具接入；保护所有写入口，处理来源删除和导出。
3. **C3 默认技法**：创建绑定、作品与会话默认配置、输入器呈现、取消／恢复语义、队列与运行快照。复用固定版本和授权校验。
4. **C4 资料初始化**：来源事实映射到现有资料能力，继承基线与续写发展共同展示；通过共享资料服务写入，不散落新增不兼容文件格式。
5. **C5 联合验收**：来源分析、创建续写、目录读取、资料读取、技法入口与新章节生成贯通；备份恢复和故障恢复一并完成。

每阶段更新同一计划的状态与验证记录；不将接口存在视为工作台接入，也不将默认勾选视为模型已读取。

## 验收用例

- 单卷／多卷来源在中段和末尾创建续写：目录顺序正确，分叉点后不可见不可读，原作不可被任何写工具修改，新章节可正常编辑。
- 同一来源创建两本续写：资料及后续修改相互独立，来源不变化；重复创建请求不产生重复书籍或资料。
- 进入工作台和新会话看到默认技法；连续发送保持默认项；取消后保持取消；普通原创作品依旧为空；重试与队列不偷偷升级版本。
- 模型实际读取准确版本入口，需要时读取辅助文件；只读来源章节可发现可读取；没有完整原文注入也能执行技法。
- 继承角色、背景和材料能通过现有面板及工具访问；缺失不补造；历史事实与后续发展不互相覆盖；中段分叉没有未来剧情泄漏。
- 来源重新分析／版本升级不会改变已有续写；删除引用、撤权、文件写入失败与进程中断有明确结果并可恢复；完整备份恢复后历史正文、资料与技法引用可用。
- 真实续写分别检查情节衔接、事实一致与文风表现；记录调用数、输入输出 token 及耗时，不把结构测试当作质量或成本结论。

## 变更边界

本轮按计划实施代码，不修改生产数据库、真实小说或现有续写数据。现有续写的补齐应是单独可预览、幂等的操作，不在启动时自动覆盖资料。新增数据结构按现有仓库迁移规范实施；真实创作资料不在该迁移范围内。
