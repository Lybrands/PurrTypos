# 原作分析资料与续写规划

## 生成契约

原作分析仍输出带证据的分类事实。`subjectKey` 使用稳定、明确的纯文本名称，`value` 可用 `[[subjectKey]]` 引用有原文依据的其他资料。模型不生成磁盘路径、不猜测资料 ID、不补造关系。已解决的伏笔标记 `lifecycleStatus=resolved`，仍有效的事项使用 `active`。

## 创建续写

仅使用所选已保存分析在分叉章节以内的事实；以下内容与创建作品在同一事务中提交，重试沿用已有创建操作。

- 人物、背景、设定继续使用已有共享 Markdown。程序将唯一匹配的显式引用解析为 `[[资料/实际文件路径|显示名称]]`。缺失或同名歧义引用退回普通文本；代码片段不参与替换。
- 原作情节在 Vault 的 `资料/原作情节` 保留创建时的快照，链接到相关人物、背景和设定。此快照不是大纲或剧情线的双向编辑入口。
- 事件和时间线形成全局故事大纲中的“原作已发生情节”；仍有效的未决情节、伏笔形成“续写起点与待推进事项”。“后续剧情规划”留空，用户或写作 Agent 再编写。
- 仍有效的未决情节和伏笔转换为版本化 Story Memory 的 `plot_thread`，在统一记忆中心作为剧情线管理，保留来源章节和证据，不预填预计回收章节。已解决事项保留在原作资料中，不重新建立开放剧情线。

原作继承基线仍只读；续写大纲及剧情线属于新作品。分析完成不会直接改写已有小说；本改动针对此后创建的续写，不批量覆盖已有续写。

## 验证

隔离数据库和临时 Vault 覆盖文件链接、缺失目标、分叉过滤、剧情线状态、重复创建、文件失败回滚及基线防篡改。真实模型生成质量、Obsidian 原生图谱及 Electron 实机效果与确定性测试分开验收。

## 分析结果与写作资料分类

| 分析页 | 事实类型 | 续写落点 |
| --- | --- | --- |
| 人物资料 | character_identity / character_state / character_knowledge / relationship | 人物资料 |
| 故事背景 | background | 故事背景 |
| 世界设定 | world_rule / setting / location / faction / item | 世界设定，地点、势力、物品保留相应类型，规则归入其他设定 |
| 故事大纲 | event / timeline | 故事大纲中的原作已发生情节 |
| 剧情线与伏笔 | unresolved_plot / foreshadowing | 仍有效事项进入剧情线管理 |
| 写作技法 | techniqueResult | 写作技法库与来源关联 |

续写起点是创建时对各类当前状态的汇总，不再作为独立分析分类。历史概览仅在旧数据实际保留时显示；无法识别的旧事实保留在待分类资料中。已有小说不因分析页改版而被重新分类或覆盖。
