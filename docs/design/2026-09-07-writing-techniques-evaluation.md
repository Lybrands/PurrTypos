## 2. 输入、评审和独立使用的隔离

每个案例有三个分开的输入视图：

1. **生成者**取得该例的 `generatorInput`、指定来源和观察、冻结的生成规范、真实宿主文件／结果契约。输入中如实保留观察的支持状态和来源范围。只在所给范围提炼；本组案例不授权主动寻找其他来源。生成者看不到 `judgeOnly`、独立使用任务及其判定条件。
2. **内容复核者**取得来源、观察、生成文件及本例判定要求，逐条检查正文中的可执行机制是否有依据。评审引用具体正文位置与观察 ID，不写“总体不错”代替判定，不索取私有推理。
3. **独立使用者**在新上下文中取得其使用任务及生成结果的名称、用途和入口，随后按入口读取必要辅助文件。不得附带来源、观察、分析过程、评审意见或标准答案。E07a/E07b 的选择任务先只提供两份名称和用途，作出选择后才开放所选入口。

复核者与生成者不得复用生成上下文充当“独立评审”。可以使用另一位人工复核者或新模型上下文辅助复核，但模型自评不能成为唯一结论。内容复核与独立使用分别留证：会指出技法缺陷不等于实际能靠它完成新任务。

`calibration` 案例 E01、E03、E04 可用于示例解释和修订；`evaluation` 案例不加入生产提示词。若后者的正文、答案或任务被用于提示词调试，应将对应来源组重新标为校准，补充未用于调试的新材料后再声明独立验证。共享原文的 E01/E04 属于同一来源组，不能拆成训练与验证两份独立证据。

这些案例不规定生成标题、章节名称、完整正文或统一文件数。正文写法可有不同措辞，只要保留对应机制、依赖与证据边界。常见但执行必需的知识可以保留；稀奇新颖不是通过条件。

E02 允许合理多文件，也允许清楚的完整单文件。若模型选择单文件且内容合格，内容质量可以通过，但**多文件原生生成与按需读取覆盖必须记为 `not_covered`**。多文件验收需要模型实际生成具有独立读取用途的辅助内容，再由 U02a/U02b 的读取记录证明无关分支未默认加载。不能手动拆开输出后宣称模型已具备原生多文件能力，也不能为达到文件数量而给模型强拆指令。后续如需更有代表性的复杂材料，应另行冻结样本，不能静默更换本例原文和摘要。

E03 的核心依赖不能因为划分辅助文件而变成可独立遗漏的两套写法；必要的展示例子可以独立，但入口和必需正文仍要完整指导“猜测如何成立、如何被新信息纠正”。

## 4. 判定与通过条件

每个判定条目使用 `pass / fail / not_executed / not_covered / blocked`，附简短理由和可复查位置，不用平均分掩盖实质错误。`blocked` 说明缺失条件，例如宿主接口未实现；不能把未执行记为通过。

**结构判定**由宿主契约的确定性检查完成：入口与元信息有效、相对路径和引用合法、文件集合完整、版本一致、完整提交才可用。材料不足分支验证正常结果与证据保存，不要求不存在的入口通过校验。提交器、恢复和取消已实现；确定性结果与模型内容质量分别记录。

**内容判定**要求该例 `requiredDecisions` 全部成立、`rejectIf` 均未触发，同时满足以下公共门槛：

- 可执行规则能映射到输入观察及原文，必要推导不升级成来源已经证实的普遍规律；不得承诺未经验证的阅读效果或全书结论。
- 正文告诉使用者如何安排文本及必要取舍；不能以评价、梗概、人物设定、复核报告或来源剧情模板充当技法。
- 内容去重不删掉执行必要条件；拆分有实际用途，共同依赖明确，入口不只是目录，也不重复辅助全文。
- 来源覆盖、不支持观察的排除理由与证据关联保存在分析结果中；正文保留影响创作选择的边界。不能把证据记录完全删除，也不能反复复制分析不足说明填充正文。
- 名称用途能表达能力与适用条件；不因句式、标题或文件数不同判错。

**独立使用判定**逐个执行该例 `independentUse`，检查实际交付文本是否满足其全部 `passIf`，并保存实际读取凭据。正文位置是“做到了”的依据，使用者自述执行了某步骤不算证据。未读来源仍无法使用、执行要靠外部分析补全，或只显示目录却未读取入口，均不能通过。E06 验证无产物消费行为，不强制写作；E08b 允许相关澄清或缩小交付，并不要求补造完整文案。

每例通过须满足所有适用判定；多人复核存在实质分歧时，记录争议对应的规则和原文，状态保留待判定，不能由生成者自我裁定。不得把“作者可能想表达”当作解决证据争议的理由。

本组 synthetic 案例通过只证明其覆盖范围内的开发行为。B 线完整验收还需要真实来源、真实 Provider 生成、合理多文件产物及后续真实写作读取证据，并通过独立内容复核。不存在单次成功便可宣称跨模型稳定、降低 Token 或提升耗时的门槛。

推荐执行顺序是冻结输入，生成，独立复核，再把生成产物送入新的独立使用上下文；这是为了隔离证据，不是生产蒸馏的强制多轮调用顺序。模型自行修订可以在一次生成中完成，但应保留最终交付和实际调用记录。失败样本要保留，不只展示精选成功输出。

只做内容草案试验时，宿主可以按明确契约返回相对路径与 UTF-8 正文，不实际落盘。此结果不得记为文件存储、提交、取消或恢复已通过。存储与恢复验收另按 P0 状态／接口契约执行，包括部分文件完成后恢复、响应丢失重试提交，以及取消与提交交错；不能让文件形状检查代替这些行为。
