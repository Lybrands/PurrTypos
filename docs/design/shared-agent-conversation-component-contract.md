# 对话业务组件使用规范

适用范围：小说写作、小说来源分析、剧本 Agent。本文约束交互组件及其接入方式；历史选择、模型请求、流式输出和恢复遵循[共享对话与执行规范](shared-agent-conversation-contract.md)。

## 组件职责

三个页面通过 `AgentConversationController` 接入 `AgentConversationPanel`，统一使用其 `Composer`、模型选择器、消息视口、任务进度、排队提示及发送/停止按钮。领域补充内容通过 `AgentConversationExtensions` 插槽提供。不能通过另外渲染输入框或接管 Enter 绕过公共规则。

`getAgentConversationCapabilities` 负责只读、会话导航和发送/排队模式。`isComposerSubmitDisabled` 是发送按钮、Enter、结构化回答的共同准入判断。Controller 提供事实状态和业务就绪条件；页面 action 仍须在真正提交时校验当前作用域，不能只信按钮的 disabled。

`composer.ready` 表示领域材料、会话和操作条件是否就绪，不包含输入框是否为空。`composer.submitDisabled` 可补充当前草稿的条件，但不能代替 `ready`，否则结构化回答可能绕过业务条件。结构化回答使用自身内容校验，不能因输入框为空而被拒绝，也不能绕过加载、暂停、停止、模型或作用域检查。

## 输入状态

| 状态 | 输入与模型选择 | 普通发送和结构化回答 |
| --- | --- | --- |
| 空闲且就绪 | 可编辑 | 有内容且有选定模型时可发送 |
| 正在执行或接收提交 | 可编辑 | 加入当前作用域的发送队列 |
| 首次加载会话/历史运行状态 | 可编辑草稿 | 加载完成前不可发送 |
| 暂停 | 可编辑草稿 | 先继续或停止当前任务 |
| 正在停止或恢复 | 可编辑草稿 | 操作完成前不可发送 |
| 无模型、无会话或领域未就绪 | 可编辑草稿 | 不可发送 |
| 领域明确只读 | 不可编辑 | 不可发送 |

只有明确只读才能令 `inputDisabled=true`；运行中、暂停中不能据此锁住输入框。加载仅阻止新提交和暂时的会话导航。Enter 提交，Shift+Enter 换行，中文输入法确认不提交；斜杠命令遵循同样的只读边界。自动增高和快捷键由共享 Composer 管理。

停止与输入就绪分开：存在可控制的运行时才允许停止；提交尚未返回 Run 或正在等待服务端运行记录时，可用 `conversation.abortDisabled` 禁止无目标的停止。断开订阅不是停止。Task 已完成而 Root 仍在执行时，仍应显示执行中并排队，不能提前开启下一轮。

## 作用域、草稿和排队

| 页面 | 草稿/排队隔离范围 | 领域输入 |
| --- | --- | --- |
| 小说写作 | 书籍与会话 | 章节、选择文本、绑定方法等 |
| 小说分析 | 来源与冻结版本 | 来源章节、分析结果及追问 |
| 剧本 | 项目与会话 | 阶段命令、集场范围、剧本材料等 |

Controller 的 `conversation.identity` 表示会话显示范围，不能随每次新 Run 改变。切换会话或来源后，旧请求不能清空新草稿、改变新作用域的忙碌状态或写入旧消息。分析页加载来源期间输入的草稿只迁入该来源解析出的版本；不能覆盖已经保存的该版本草稿。

发送或排队时消费的是当时提交的草稿，之后继续输入的文本不属于该提交。队列项冻结消息、作用域及模型请求配置，用户后来切换模型不修改已经排队的请求。显式传入的结构化回答不清空用户输入框。

共享组件展示队列，由领域接入层串行执行其业务提交。只有当前作用域加载完成且没有阻塞任务时才消费队列。分析页还须等待已有分析产物载入，避免把追问误当成重新分析。写作和剧本保留现有会话运行时；分析使用 `createScopedComposer` 管理页面存续期间的草稿与队列，不另建持久化任务系统。

所有待发送消息必须具有入队时生成的稳定 ID，不能以数组下标或显示顺序充当身份。共享 `QueuedSubmissions` 提供逐条编辑、保存、取消及删除，并以滚动列表展示全部队列项。三处 Controller 的 `updateQueuedSubmission(id, patch)` 写回真实待发送队列；`patch=null` 删除，非空 patch 只修改正文和编辑状态，保留原位置、ID、作用域、模型配置和领域上下文。空白正文不能保存。

开始编辑即暂停该会话的队列消费，包括当前 Run 结束时的自动消费。保存或取消后解除编辑状态；其他仍在编辑的消息继续阻止消费。编辑期间的新输入继续排队，不能越过旧消息。取消只丢弃队列编辑草稿，不修改原正文或主输入框。切换会话、删除消息或卸载组件须释放编辑状态，防止队列永久卡住。

删除仅移除尚未领取的队列项，后续消息身份和相对顺序不变，也不取消当前 Run。消息被领取后就不再属于可编辑队列，迟到的保存/删除操作返回失败，不能改写已经提交的请求。不同会话与来源之间的同类操作必须按队列项归属校验。队列显示和实际消费都使用最新状态，不能将旧渲染快照重新写回队列。

提交失败不能覆盖后来编辑的草稿。分析队列在明确未接受时暂停：草稿未再编辑则恢复草稿，否则保留待发送项；共享队列区域通过 `queuePaused`、`retryQueued`、`clearQueued` 展示重试与清空入口。服务端已接受后的刷新失败不视为提交失败，也不能因此自动再发一次。页面卸载后的草稿持久化及网络结果未知时的命令对账属于各运行时契约，不由输入组件伪造成功或重试。

## 模型配置和业务扩展

底部闪烁的等待提示只表达执行状态，使用 `getAgentProcessingLabel` 从公开生命周期判断，例如正在思考、制定计划、执行工具或生成回复。不得以 `commentaryBlocks`、`agentProgress.text`、`planningProgress.text`、正文或当前流式正文作为等待提示，即使文字短、属于当前调用或尚未提交。公开文字只在对话正文/执行记录中按真实 chunk 更新；等待提示的显隐延迟不得延迟文字更新。Run 已终止时停止展示等待提示，不能只依赖页面的 loading 标记。

三处都传递 `selectedModel`、`modelConfigs`、`selectModel`、`updateModel`、`openModelSettings`。`updateModel` 使用完整 `ModelRuntimeConfigPatch`，包含 `modelPreferences`；必须接到应用配置更新入口，不能只显示参数控件而没有保存回调。运行中的模型选择变更用于后续提交，不能修改已冻结请求。

来源确认、章节范围、写作方法、分集分场、审批及交付物保留领域实现。快速分析等独立业务操作必须遵守作用域加载和并发限制，但不改写成普通聊天业务。组件一致不要求工具、权限、附件结构及占位文案完全相同。

## 回归要求

### 诊断与历史恢复

诊断面板只在用户主动打开或提交新任务时显示；历史事件回放、重连和组件重新挂载不能将关闭的面板唤醒。关闭时卸载订阅数据的视图及计时器，保留手动打开入口。诊断数据采集与面板显示分离，不得以关闭诊断为由停止对话事件消费。

执行段和技术明细仅在展开时挂载正文；Planner 原始输出仅在展开时读取。折叠的 HTML `details` 不等同于 React 内容未挂载。

剧本首次恢复历史按事件页提交视图，追上实时位置后恢复逐 chunk 提交。共享事件读取器在连续处理超过时间片时让出主线程；消费成功后才推进游标，取消后不能继续消费缓冲页。该调度不更改用户的模型配置、事件内容或事件顺序。

### 检查项

- 三个真实 Controller 工厂使用同一状态矩阵，覆盖运行中排队、只读、加载、无模型、无会话、暂停、停止与恢复。
- 挂载公共 Panel 验证点击和 Enter 同步阻止提交，Shift+Enter 与输入法确认不误发，切换会话使旧编辑器失效。
- 覆盖来源/版本草稿隔离、加载期草稿迁移、模型快照、队列串行执行、迟到失败及新草稿保护。
- 覆盖全部队列项可操作、空白拦截、编辑保存/取消、输入法确认、稳定 ID、逐条删除、编辑期不消费、取消编辑后恢复、主输入框不受影响、跨会话操作和已领取项拒绝变更；验证最终请求使用编辑后的正文及原模型配置。
- 输入契约改动运行 `npm run check:agent-refactor` 和 `npm run build:web`；涉及模型输出时，另按共享规范验证真实 chunk 与恢复链路。DOM/模拟服务测试不能代替真实 Provider 生成质量验收。
