# 来源写作方法蒸馏

小说分析 schema 2 将故事事实、来源观察与最终写作方法分开。来源观察仍存储在 craftCards 字段与证据表中，但不再作为方法正文，也不预设八类。

## 生成与检验

1. 按冻结片段读取原文，提取硬事实和有证据的机制观察。
2. 分层归一并聚合观察。事实保留局部证据，最终写作观察只取聚合结果，不重新加入局部碎片。Recipe 5 对单一、已冻结且不超过 4,000 字符的片段，将提取、片段内归一和故事概览合并到一个模型单元；更长片段及多片段保留分层流程。
3. 校验逐字证据和范围。证据存在不等于结论成立。
4. 从有效观察蒸馏一个完整方法：目的、适用情境、限制、执行步骤及理由和检查点、常见失败、完成检查。
5. 只把方法交给试写单元，不提供原文或来源观察。生成两个新场景的普通写法与应用方法后的写法。
6. 独立调用根据来源观察及首次试写复核并修订方法。
7. 用修订后的方法再次做两个场景的试写。
8. 单独复核证据支持、抽象程度、执行性、迁移效果和适用边界。每个维度必须给出明确结论及依据。

固定增加五个模型单元；每个单元由宿主提供完整绑定输入，再通过正式工具提交产物，模型轮次数不等于单元数。一次修订控制成本，不无限自循环。

## 执行与配置约束

- 保留用户模型配置及现有解析优先级。Provider 默认、显式推理强度、思考模式、温度、输出上限、上下文配置均不得由本次编排优化覆盖或写回。
- 内部单元通过 `novel_analysis_unit_input` 接收材料，声明完整输入所需的上下文预算；预算不足则拒绝执行，不截断输入或伪造读取工具历史。材料标记为不可信指令来源，原文仍是证据，并保留来源绑定与输入摘要。
- 内部单元只执行当前阶段的任务。全流程方法指导和完整 Planner 计划保留在主流程；单元中的 `analysisFocus` 保留用户关注点，用于当前阶段取舍。试写单元继续只获得写作方法及提交契约，不接触来源材料。
- 上游失败在 PurrA 的模型调用层完成恢复后，如果单元 Run 已失败，外层不再自动重跑整个单元。输出截断等可安全修复的候选错误仍允许有限的单元重试。用户手动恢复、已完成单元复用及取消行为保留。
- 所有公开文案继续消费真实 Provider chunk，经持久化与 SSE 到前端。输入、候选 JSON 和内部完成回复保持私有。
- 短片段路径为 9 个持久化单元、6 个模型单元，保留证据校验、两轮试写、修订、最终评估及人工审核。标准一次提交成功的模拟链路共 15 次模型调用（主流程决策、规划、最终呈现各一次，每个内部单元两次），不代表真实模型必然以相同调用次数或耗时完成。
- 已持久化任务的冻结编排不改写；新建任务采用 Recipe 5。服务需加载新代码后才能验证新流程，旧 Run 的耗时与输入仍作为历史证据保留。

## 产物与入库

`writingSkill` 是结构化完整方法，`distillation` 保存两轮试写、修订记录和复核结论。试写材料与来源证据不进入方法正文。

最终试写关联 `testedSkillDigest`，发布时重新核验。方法变化后不能复用旧的迁移检验记录。模型复核失败显示 `needs_revision`，不能创建方法库候选；通过显示 `pending_review`，仍需人工审核。

候选转换不再调用模型或按分类拼接卡片，而是将已检验方法渲染为一个 `primary` 方法与包含它的方案。重复创建返回同一候选批次。用户主动发布并绑定后，完整方法按主方法规则注入，受上下文预算及本轮排除项约束。

对话结尾介绍已保存结果，不能临时再生成另一套方法。追问保持只读；修订应重新运行蒸馏，追问不会隐式改写已保存版本。

## 验证边界

模型执行的迁移检查不是盲测、人工偏好实验或普遍有效性的证明。两个新场景只能揭示部分可执行性和迁移问题；仍可能出现模型自评偏差或证据解释错误。结果页保留普通写法、应用方法后的写法和复核理由供人工判断。

测试覆盖字段/证据/摘要约束、失败阻断、正式持久化与工具流、绑定注入，以及界面展开。真实 Provider 验证结果另行记录，不以模拟测试代替。

## 旧数据清理

`scripts/clear-legacy-novel-analysis.py --db PATH` 默认只报告范围，`--apply` 才执行。运行前生成权限为 0600 的 SQLite 备份；拒绝删除仍被续写正史、作品绑定或外部方案引用的数据。清理旧分析、关联运行/任务/产物和分析派生方案，保留来源正文、书籍和独立方法。脚本不在应用启动时自动运行。
