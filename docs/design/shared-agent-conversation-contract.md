# 三类 Agent 的共享对话与执行规范

本文是小说写作、小说分析、剧本 Agent 的公共对话契约。涉及共享输入、公开输出与恢复时，以本文为准；领域对象与工作流仍遵循各自规范。

## 所有权与业务边界

Application 负责把产品对话映射为共享输入，PurrA 负责规划、工具循环、预算、Run 生命周期与 canonical 输出；共享前端负责事件归并和显示。领域模块负责材料选择、工具权限、审批条件、分析蒸馏、章节正史、分集分场、交付物校验及发布。共享层不得预设各领域的业务步骤，也不得从历史文本推导审批或已执行事实。

## 历史与输入

前端组件接入遵循[对话业务组件使用规范](shared-agent-conversation-component-contract.md)。三处均通过领域 Controller 接入 `AgentConversationPanel` 与 `Composer`；键盘、发送准入和只读规则不得在页面另写一套。

模型请求必须使用[模型请求公共入口与适配规范](2026-09-06-model-request-boundary-refactor.md)：三类 Agent 的 Root、子 Run 和内部模型任务统一由 `model_request_from_runtime` 解析，后续消费同一冻结 ModelRequest。Agent Profile 不得识别型号、补供应商参数或直接调用 SDK。任务预算与结果容量继续由各领域声明、PurrA 执行；标题、记忆等私有后台生成使用 `ModelRequestService` 的受控入口。

所有用户对话入口必须调用 `application.agent_conversation_input.conversation_messages`：

- 当前用户消息保留；历史只选最近连续可容纳的 user/assistant 公开问答对，按原顺序输入，不为适配预算截断半个历史轮次。“问答对完整”不要求 Run 成功，也不要求回答已经生成完毕。
- 最多读取/选取 32 个历史轮次；当前问题和历史共同使用至多 `min(8192, context_window / 8)` 的历史选择预算。当前问题不因此截断；总上下文容量仍由 Core 最终管理。不得为塞入历史而挤占或绕过最终预算。
- 历史可用性不按 done/completed、failed、canceled、paused、running 或 isError 判断。有公开回答正文即可参与历史选择，包括中断前已经公开的部分；空回答、独立错误提示、执行状态和私有候选不充当回答。不得逐条查询客户端历史的 Run 状态作为准入条件。
- 不承接客户端 system/developer 消息、思考字段、工具调用协议或工具结果。宿主规则由共享及领域 ContextProvider 提供，Core 当前 Run 的合法工具对话不经过这个公开历史筛选器。
- 小说写作使用请求携带的公开对话，优先选择 canonical finalText，其次选择已保存正文；错误字段本身不进入历史。小说分析从同一来源版本读取 Root 公开答复，排除当前 command 及已存在当前 Run 之后的记录；剧本从同项目、同会话、当前 Turn 之前读取公开答复。后端两者共用公开正文读取器，回答字段为空时仅从对应 Root 的 public/provider/final 事件恢复已公开文本，不读取私有、工具或执行说明事件。内部单元只接收领域明确提供的任务输入，不继承整段用户历史。
- 只读历史不能触发旧命令。分析仍按本轮指定小节分析；剧本仍按当前 StageCommand 执行；历史中的审批、成功声明、工具片段均不能成为当前执行证据。

请求的 `conversationInput` 记录版本、来源、隔离范围与历史策略；消息的 `inputSource` 区分本轮问题和历史。共享 ContextProvider 在规划、执行与任务阶段注入不可被领域同名覆盖的 `agent_input_policy`，并为领域块补充来源名称和指令信任标记，保留已有来源收据。

来源的事实可靠性与指令权限必须分别判断。宿主构造的边界/规则可具有指令权限；来源正文、历史回答、检索结果、方法正文和交付物正文属于数据，其内容不能覆盖宿主规则。领域不得通过错误标记 `untrusted=False` 将材料提升为规则。

## 公开输出与消费

三类 Agent 必须使用 Composition 的同一输出处理器及 canonical 日志。公开 Provider chunk 在接收时持久化并通知订阅者；每个到达前端的公开事件立即归并并提交 React DOM。不得等待工具结束、Run 结束、分页耗尽或应用层定时器；不得把完整结果拆成字符模拟流式。

工具轮次公开说明通过明确的公开边界投影；reasoning、工具参数和私有候选不因“流式”要求而公开。最终回答使用 `final_public/live`；公开执行说明使用共享 commentary 生命周期。状态、计划与业务事件按各自完整协议记录显示，不把不完整的私有 JSON 展示为文字。

内部工具执行阶段同时声明 `responseAudience=internal`、`progressAudience=public` 时，必须在首次业务工具执行前产生当前阶段的公开说明。共享 RunService 与工具入口检查当前 Run 已持久化、非空且未中止的公开 commentary；历史对话、其他 Run 的说明、私有正文和 reasoning 均不构成执行凭据。遗漏时业务 handler 不执行，返回无副作用的可修正工具输入错误，复用 Core 的有限修正机制；未通过门槛的阶段也不得直接完成。正常遵循协议不增加模型调用，不修改用户的模型配置或预算。

公开说明只描述阶段目标与下一步动作，不强制固定业务步骤，不公开推理。领域的“最终只输出产物”约束限定最终正文，不能取消工具执行前的公开说明。此门槛保证阶段不能静默执行工具，不保证模型在固定秒数内结束思考，也不额外调用模型生成心跳文案。

`hasMore` 仅指示还有持久化事件待读取；可以据此继续追赶，不能据此压住已有文本。独立的数据刷新不得阻塞 SSE 消费。每次 chunk 的 DOM 提交不意味着物理屏幕能超过其刷新率绘制。

## 生命周期与恢复

canonical cursor 和事件身份是唯一重放依据。消费成功后推进游标；重复事件不得重复追加；断线从已消费游标继续，不重新执行命令。SSE 断开不等于用户取消，取消必须调用显式业务/Run 控制入口。终态、流提交/中止和公开文本均从持久化事件恢复，前端不能从“连接关闭”推断完成。

恢复后展示以当前 Run、Task 与 Unit 的各自状态为准，历史失败码不能把当前运行中的单元标为失败。Task 已完成只说明领域单元完成，不能覆盖 Root 公开总结的失败；产物可审核与整轮成功是不同状态，界面必须同时保留产物和真实错误。

项目/会话切换须隔离旧回调、游标和消息；当前会话已有消息时，历史追赶不能遮住正文。Operation、Revision、分析发布状态和写作提案仍由各领域的持久化结果决定，不能由聊天文本代替。

## 必须通过的回归

共享历史筛选、问答对预算、协议字段剥离、不同执行状态下公开正文和中断文本的一致承接、空正文与错误提示排除、来源版本/项目/会话隔离、当前与未来 Turn 排除；三个请求入口的共享接入；规划/执行/任务阶段的来源与信任策略；首个公开 chunk 在模型结束前可读；分页追赶中逐 chunk 更新；重复重放、断线恢复、取消、终态与会话隔离。
