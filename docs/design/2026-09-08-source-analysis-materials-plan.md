# 来源分析产物与证据引用改造

日期：2026-09-08。

状态：已实施分类资料界面、归一阶段证据引用、取消新概览生成和续写继承调整；离线回归及真实生成、保存、继承、入口读取链路通过。A5 的生成内容质量与成本评估尚未全部通过，不视为质量验收完成。

## 目标

来源分析直接服务于两类交付：可继承的小说创作资料，以及可从入口使用的写作技法。产物名称、内容组织、保存结构和续写工作台的资料入口一致。保留可追溯来源，不要求模型在各阶段反复抄写引文。

本计划补充并修订 [来源小说与续写工作台的完整继承](2026-09-08-source-continuation-inheritance-plan.md) 和 [写作技法改造计划](2026-09-07-writing-techniques-1.0.0-plan.md)。旧实施记录保留为历史；其中“故事概览作为 background 正史记录继承”的行为由本计划取代。

## 已确认的方向

- 取消“事实脉络”这个面向用户的产物概念，保留底层有范围、来源和实体身份的结构化事实。
- 分析结果按人物资料、世界与故事背景、情节与续写起点、写作技法组织；来源依据作为按需展开的关联信息。
- 不再要求额外生成一份宽泛故事概览，也不将摘要作为独立硬事实写入正史。
- 用指定范围内的“续写起点”帮助用户理解当前进展、冲突、人物状态和未决问题；其内容引用正式资料，不成为第二套事实源。
- 证据一次提取和校验，后续优先引用稳定 ID；确需理解原文时按需读取。

## 产物与继承契约

| 产物 | 内容 | 续写用途 |
| --- | --- | --- |
| 人物资料 | 身份、状态变化、知情范围、明确关系 | 初始化人物资料的原作基线，并保留实体身份和时间范围 |
| 世界与故事背景 | 背景、世界规则、地点、势力、重要物品 | 对应背景及已有设定类型，不补造不存在的属性 |
| 情节资料 | 关键事件、先后关系、未决问题、明确伏笔 | 在已有情节／记忆／伏笔入口可见可读；事件不能伪装成物品或普通设定 |
| 续写起点 | 截至所选分叉点的进展、状态与未决事项 | 可重建的阅读视图，引用资料 ID，不加入正史原子记录 |
| 写作技法 | 可执行的语言、叙述、节奏、铺垫和风格方法 | 沿用准确版本授权、默认手动选择、从 SKILL.md 开始读取 |
| 来源依据 | 稳定来源版本、章节及片段定位 | 核查、纠错、范围校验，按需显示正文 |

生成规范与资料契约同时调整，不能只把 facts 按类型重新分栏就认定完成。人物资料需围绕稳定实体组织；同名不同人物不合并，别名有明确依据才归一。人物关系关联参与实体，不能把关系标题误建成新人物。

事实保留原文明确内容、角色认知和不确定性之间的区别。人物曾受伤是历史状态，不是永远不能康复的约束；多个时间点的状态必须可区分。未经确认的伏笔推测不能作为硬事实自动继承。

复用现有共享 Markdown 资料及服务，SQLite 记录分析版本、结构化事实、证据索引和继承身份。来源分析是来源的独立版本；只有创建续写时，才初始化目标作品资料。保留只读原作基线及独立可编辑发展段，不新增平行 Story Memory 副本。

## 续写起点与范围

- 来源分析尚未选择分叉点时，展示分析覆盖末端的资料摘要，明确覆盖范围；创建续写时按用户所选章节重新计算。
- 摘要只引用该分叉点之前成立且有来源的资料，不能沿用全书摘要再简单删去引文。
- 以已有资料分组展示为默认实现，不为改名新增一次强制模型归纳。需要连贯摘要时作为可选派生内容，明确其依据和范围。
- 不允许摘要重复注入或覆盖原子事实；删除摘要不应导致人物、背景或续写约束丢失。
- 跨分叉点归并的事实不能只以最后一处证据过滤而丢失较早状态：保留可按章节恢复的事实版本与引用范围，再组装当前状态。

## 证据契约与成本控制

1. 模型首次分析已读取的原文时提供必要的连续短引文，或引用宿主预先提供的片段 ID。宿主负责匹配、范围验证、定位及散列，不让模型计算字符偏移。
2. 证据身份绑定不可变来源版本、章节和准确片段，复用同一片段而不丢失它与不同判断的关系。重复文本匹配多处时使用已绑定片段范围消歧，不能静默选择第一处。
3. 事实和写法候选引用 evidenceIds。归一阶段保留或合并合法引用集合，宿主校验 ID 属于当前来源和已读取范围，未知或越界引用不可提交。
4. 后续输入默认使用资料正文、观察正文和证据 ID；支持批量按需读取证据。写作技法涉及具体语言配合时允许读取必要引文，不能为了省 token 使模型无法判断文风。
5. 每条判断保留最短充分证据，不机械规定仅一条。时序、关系、重复及节奏判断可能需要多处；宏观范围结论不能用一句话冒充完整依据。
6. 逐字匹配只证明引用存在，不证明推论成立。候选仍需符合内容约束和用户可核查要求，不将通过定位验证显示为语义完全正确。
7. UI 默认折叠来源依据，展开时读取原文；正式资料和默认模型上下文避免反复嵌入长引文。冻结来源删除、续写独立副本、导出与备份恢复必须保持引用可解析。

引用 ID 可能降低重复文本量，但按需工具读取也可能增加往返。实施前后的调用次数、输入输出量、耗时和可用资料质量必须用可比样本实测，不预先宣称性能收益。

## 实施顺序

- **A1 资料及证据契约**：明确资料种类、实体关系、时间状态、证据注册和引用解析、摘要的派生身份；锁定每种资料在现有工作台的真实保存和读取位置。
- **A2 分析执行与提示词**：调整提取／归一工具、输出校验和恢复状态；移除强制宽泛概览阶段，后续证据改为引用及按需批量读取，修正旧默认提示词。
- **A3 保存与继承**：统一 review／publish 数据契约及版本；续写初始化消费分类资料，取消概览正史记录；分叉点过滤与历史状态共同校验。
- **A4 结果界面及工作台**：分类资料可浏览、核查及修订，显示未定与冲突；技法编辑继续使用共享 Tree 与 Markdown 业务组件；证据按需展开。
- **A5 联合验证**：分析、审核保存、创建续写、资料工具读取、入口技法读取、正文生成和备份恢复贯通，记录质量与成本。

每步明确完成状态和证据后再推进；全部阶段完成才算这轮业务改造交付。

### 本轮实现与验收边界

- 新 recipeVersion 6 不再创建概览聚合单元；历史概览与旧单元保留读取和恢复支持。
- 归一输入以 evidenceId 代替重复引文，readAnalysisEvidence 只能读取当前运行冻结输入中的依据。未知、跨来源以及被取消运行的引用读取均拒绝。引用目录可从冻结产物重建；本轮未迁移历史证据表，也未把全部持久化引文改成独立引用表。
- 归一事实仅更新有依据的实体名称，未返回的原子事实由宿主保留；跨章节重复事实保持独立范围，精确去重由程序负责。
- 提取阶段新增 appendAnalysisFacts，每次最多保存 8 条已确定资料并即时校验引文；最终提交自动合并已保存批次，无需再次抄写。重放相同工具调用不重复落库，取消运行不能继续写入。分批保存减少单次提交负担，但不保证 Provider 一定及时结束推理。
- 人物和背景设定沿用共享 Markdown 资料；情节使用已有 continuation_material_baselines 的 plot 分类和冻结正史记录，不再创建普通设定实体。工作台通过情节资料入口读取，写作上下文读取冻结情节记录，避免因为普通资料已使用 Markdown 而漏掉情节。
- 继承正文只展示资料及章节出处，完整证据保留在冻结记录中以便核查与备份。来源概览不再成为新增续写的正史记录；已有续写不重写。
- 结果按人物、背景设定、情节及写作技法分组，未知类型保留在待分类资料中。文本资料可以通过共享 Markdown 编辑器修订；历史结构化对象仍只读展示。续写起点返回所选分叉点内的资料 ID，不新增模型摘要调用。
- A5 包含真实模型验证。初次 E02 实测发生 tool_call_truncated；加入资料分批保存后的运行完成，但推理成本仍高，技法内容存在固定句长等过度泛化，不能认定成本和内容质量改善；详见 [验证记录](../validation/2026-09-08-source-analysis-materials.md)。

## 历史数据和验收

不把此前清除旧写作技法数据的授权扩大为删除真实来源或已创建续写。新分析使用显式版本契约；旧分析和运行可识别可读取，不在启动时自动重写正史。已有续写不静默升级或覆盖，必要升级另提供明确可预览的操作。

验收至少覆盖：同名／别名人物与关系，状态前后变化，角色不知道的秘密，中段分叉和末尾分叉，来源中断或缺失字段，冲突保留，未知／越界证据 ID，重复引文消歧，短引文不能支撑宏观判断，来源删除后的冻结读取，重试幂等，取消／恢复，备份恢复。

用相同来源、模型与配置比较旧／新路径；分别记录分类资料完整性、准确性、续写衔接、技法可执行性和实际模型耗时用量。离线测试不作为真实生成质量或性能通过证据。
