## 1. 使用模式与选择的作用域

### 1.1 默认与继承

- 新小说的默认模式为 `manual`，界面显示“仅手动指定”；没有历史设置时也使用该默认值，不从旧主方法绑定推断自动模式。
- 小说可以保存新会话的默认模式。新会话建立时复制该默认值；之后会话独立保存 `manual | auto`，输入框下方切换的是当前会话模式。
- 修改小说默认值只影响后续新会话，不回写已有会话。切换会话模式作用于下一次提交，不改变已准入 Run 的模式快照。
- 手动选择及上传只属于待发送的本轮输入，不自动延续到下一轮。宿主确认请求已准入后清空待发送选择；准入前失败保留。准入后失败或恢复读取该 Run 的原始选择，不重新采用当前输入器配置。
- 如果请求先入队，宿主受理入队时即冻结本轮模式、选择和上传身份并清空已受理输入；实际执行时重新校验同一选择的版本与权限，不从届时的 UI 重新取值。授权已失效则该排队请求需要重新选择，不升级或扩大范围。
- 长期绑定只提供自动模式下的候选授权，不等于手动模式下的已选内容。进入手动模式且未添加任何技法时，不搜索、读取或注入旧绑定。

### 1.2 选择优先级

用户手动指定为本轮必选；自动模式可在授权范围内补充。相同技法同一版本去重，保留所有选择来源，正文只加载一份。同一技法被手动指定多个版本时拒绝本次准入并说明冲突，不能默选最新版本；自动候选与手动项版本冲突时跳过自动候选。

自动候选之间按本轮自动选择结果的顺序逐个准入：先通过的候选保留，后续与已准入版本冲突的候选整体跳过并记录原因，方案不能只删冲突成员。候选顺序和最终选择写入本轮记录，恢复不重新排序。这只是版本准入规则，不表示先后顺序能覆盖写法上的语义冲突。

同一版本经多个方案引用时去重文件读取，但保留各方案组合说明。无法满足某个方案的完整成员时，不能悄悄把该方案拆成部分成功。

语义上的写法差异不等同于非法数据。作者通过方案组合说明表达条件和取舍；模型按本轮创作要求应用。若已选技法的要求确实无法同时满足且没有取舍依据，说明具体冲突并请求用户选择，不额外引入每次必跑的冲突评估调用。

## 2. 授权与方案成员

### 2.1 长期授权

小说的技法设置区域管理允许自动使用的技法或方案版本。授权对象是准确的 `techniqueId + versionId` 或 `schemeId + versionId`，不是整个本地目录；首次使用不自动授权全库。

授权一个方案版本即授权在该方案下使用它的完整、冻结的成员集合。该授权不会使成员自动成为可脱离方案独立搜索的候选，也不会覆盖方案后续新增版本。自动搜索只返回这本小说被授权的顶层条目名称和用途，不向模型提供未授权库目录。

用户可在手动选择器浏览本机活动技法库。明确选择技法或方案会授予本轮所需的临时使用权限，即使此前未加入小说自动候选；这不是长期绑定或扩大自动搜索范围。

### 2.2 固定版本和活跃权限分别验证

每个长期授权保存稳定授权 ID 和递增的 `generation`；Run 快照记录实际准入的授权 ID、代次、顶层对象及成员版本。按需读取时重新校验授权仍有效；版本固定不代表永久授权。

- 手动方案在准入时必须完整可用；缺失、已归档或文件损坏的成员导致本次选择失败。
- 自动方案不可用时跳过该候选，记录跳过原因；不声称已使用，也不偷偷升级成员版本。
- 撤销方案授权使经该授权获得的成员访问一并失效。存在其他独立有效授权时，只有该 Run 本来就准入的授权路径可以继续使用，不临时寻找旁路。
- 授权变更通知受影响的活跃 Run。发送下一次模型请求、读取文件及执行后续工具前都验证权限；撤销后停止受影响任务并提示重新选择，恢复运行也遵守该规则。
- 已发送给 Provider 的内容无法收回。取消在途调用采用当前共享运行机制；不能承诺撤销能抹除已经发生的读取。历史查看使用保存的证据记录，不等于授权重新调用模型。
- 新授权或重新启用不复活旧代次，用户重新发起写作后获得新快照。

## 3. 技法文件、方案与版本

### 3.1 作者内容

入口固定为根目录的 `SKILL.md`，采用 UTF-8 Markdown，YAML 头部必需字段：

```yaml
---
name: 危险临近时收窄叙述
description: 用于危险逼近的局部场景，通过即时动作与感官信息控制篇幅，并在安全后展开较长描述。
---
```

`name` 是可读名称，允许中文，不要求 Codex 技能的英文目录命名规则；`description` 说明能力和适用时机。可选 `tags` 为字符串列表，用于检索，不影响正文结构。宿主生成 ID、版本和时间，不要求作者填写内部字段。使用 YAML 安全解析器；不接受执行型标签、重复键和非字符串名称/用途。

首版辅助文件支持 UTF-8 `.md` 和 `.txt`。不执行脚本、不自动获取外链，不把二进制附件作为技法指令；以后增加格式需单独定义读取规则。目录及文件标题由作者决定，没有强制 `references/`、示例目录或数量模板。

引用采用标准 Markdown 相对链接，可带标题锚点。正文中的链接只提供可验证定位，何时读取由正文说明与任务决定。相对路径按引用文件所在目录解析，允许在技法根内返回上级；规范化后越过根目录、绝对路径、URL、盘符、符号链接和大小写/Unicode 归一后冲突的文件均不可用于包内读取。写入 API 使用根相对规范路径，不接受 `..` 路径段。

未被入口及后续引用链触及的辅助文件不会自动读取，但不因此禁止保存作者保留的附注或备用内容。对生成结果复核时，提醒移除无用途的文件，或为使用所需内容补充入口说明；这属于内容质量要求，不是所有文件必须可达的结构门槛。可选内容通过条件说明引用，不要求默认读取。结构验证检查实际包内引用的路径与存在性，不假装能判定所有自然语言条件。

### 3.2 身份与完整版本

公共引用形状统一为：

```json
{
  "kind": "technique",
  "id": "host-generated-id",
  "versionId": "sha256-of-content-tree"
}
```

`kind` 为 `technique | scheme`。内部 `storageScope` 区分 `library | run_input | analysis_candidate`；对写作模型保持同一入口和文件读取行为，不形成 AI 专用正文格式。

技法内容版本根据格式版本及按规范路径排序的文件清单计算 SHA-256；每项包含相对路径和原始 UTF-8 文件字节的摘要。所有入口元信息都属于版本内容；名称或用途改变也形成新版本。应用内部身份、时间和授权不参与内容版本计算。

版本快照包含全部作者文件及宿主管理的 `manifest.json`，后者记录对象身份、格式版本、文件路径、大小和摘要。清单由宿主生成并核对，不是单文件技法作者必须额外编写的文档。

完整快照不可原地编辑。修改通过草稿形成新版本，小说、方案和已有 Run 不自动升级。复制或导入技法时可以生成新身份，但相同字节对应相同内容摘要；不因此覆盖原对象。

### 3.3 方案格式

方案作者内容为 UTF-8 `scheme.json`，含 `schemaVersion: 1`、`name`、`description`、`composition` 和非空 `members`。`composition` 是可为空的 Markdown 组合说明；`members` 按作者顺序保存准确的技法版本引用。只允许技法成员，不递归嵌套方案。

成员列表顺序用于展示和阅读，不隐含后者覆盖前者。同一技法不得包含两个版本；相同版本不得重复。方案版本由规范 JSON 内容计算，引用更新和组合说明更新都会形成新版本。独立技法的生成不自动创建方案。

### 3.4 工程限额与读取预算

首版可配置的文件准入默认值：单文件 256 KiB、完整技法 4 MiB、128 个作者文件、8 层目录；名称 120 字符、用途 1000 字符，方案最多 64 个成员。这些是实现初值，不是要求生成达到的数量或篇幅，需在打包、跨平台与真实样本验证中调整。

写作读取默认按完整文件提供。是否能读入还受当前模型上下文预算约束；不因文件通过大小限制就保证能注入，也不通过静默截断入口或必读内容完成任务。自动候选超出预算可跳过，手动项或已采用技法的必需文件无法容纳时返回明确的预算错误，供用户减少选择或修改技法。

首次辅助文件读取前必须读过同一版本入口。重复读取去重，并使用现有证据体系记录实际送入模型的文件；上下文压缩、恢复或模型调用切换后，宿主确保当前任务仍有必要的入口规则，不能仅凭历史读取标记宣称模型当前持有正文。

## 4. 手动上传与草稿生命周期

### 4.1 仅本轮使用的上传

首版接收独立 `.md` 入口、目录及 ZIP。目录/ZIP 必须能识别唯一 `SKILL.md`；单独上传的其他名称 Markdown 可在导入预览中明确作为入口转换。缺少必需元信息时显示可编辑预览，不能让用户必须先了解内部 ID。

宿主把文件复制到受管理的 `run-inputs/<inputId>/` 并校验、冻结版本。浏览器通过上传取得字节，Electron 可读取用户选择的目录；不接受前端任意路径当作服务端可读文件。ZIP 解包执行与文件准入相同的边界检查，不执行归档内容。

上传分两步关联：提交前绑定会话输入暂存项；准入时绑定唯一 Run。准入后的快照随该 Run 的历史、恢复和完整备份保留。它不进入长期库目录或自动搜索索引。后续轮次如需再次使用，须重新明确选择，不从历史消息自动加载。

移除未发送的上传项或删除相关会话时，只清理没有 Run 引用的暂存内容。已经被 Run 引用的快照，只有关联运行历史也被明确删除且无其他引用时才能回收；首版不按时间自动清理这些版本。

“存入技法库”是独立操作：复制为库中的新草稿或显式选择更新对象，不覆盖上传快照，不自动发布、绑定或授权。复用已发布技法的手动选择直接引用其固定版本，不重复复制文件。

### 4.2 草稿状态与身份

草稿有宿主生成的 `draftId`、所属对象/分析任务、`draftRevision`、状态及文件集摘要。状态为 `editing | sealed | cancelled`；失败或暂停的 Run 不等于取消草稿。暂停后可按持久引用继续 `editing`；已取消草稿保留可查看内容，再次编辑从它复制新草稿。

用户编辑与 Agent 写入共用乐观版本检查。生成中的草稿若被用户修改，旧 Agent 写请求因版本冲突停止覆盖，重新读取后按当前任务决定继续，不无条件重试旧内容。

编辑操作生成不可变的文件集代次，通过原子更新草稿头指向新代次。UI 只投影当前作者文件，历史代次和操作回执由宿主管理。这允许多文件重命名与引用修正作为同一次编辑提交，避免暴露半套变化。

建议管理布局：

```text
writing-library/
  techniques/<id>/record.json
  techniques/<id>/drafts/<draftId>/state.json
  techniques/<id>/drafts/<draftId>/generations/<revision>/files/SKILL.md
  techniques/<id>/versions/<versionId>/manifest.json
  techniques/<id>/versions/<versionId>/files/SKILL.md
  schemes/<id>/...                         # 同样区分草稿与版本
  run-inputs/<inputId>/manifest.json
  run-inputs/<inputId>/files/SKILL.md
```

对象 `record.json` 是身份、草稿/发布版本指针与库中归档状态的正式文件元数据；SQLite 中的对象目录是可重建索引。授权、绑定、会话配置和运行状态仍是 SQLite 中必须保留的正式业务数据，重建索引不覆盖它们。

## 5. 文件操作与完整提交协议

### 5.1 业务操作契约

以下是服务/工具层统一语义；HTTP URI 可沿现有路由风格实现，不能另造行为不同的前端专用写入链路。

| 操作 | 主要输入 | 输出及保证 |
| --- | --- | --- |
| `createTechniqueDraft` | `operationId`、创建来源/所属任务、可选已有版本 | `draftId`、`draftRevision`、状态；同一来源创建操作重试返回同一草稿 |
| `getTechniqueDraft` | `draftId` | 当前版本、作者文件路径/摘要及状态，不自动加载全部正文 |
| `readTechniqueDraftFile` | `draftId`、`draftRevision`、`path` | 准确代次的完整文件及摘要；代次不存在则报错，不改读最新 |
| `applyTechniqueDraftChanges` | `draftId`、`expectedDraftRevision`、`operationId`、`changes[]` | 新版本与摘要；一次 changes 可含完整内容 put/delete/move，用于原子处理相关文件 |
| `sealTechniqueDraft` | `draftId`、`expectedDraftRevision`、`expectedTreeDigest`、`operationId` | 完整不可变快照引用；验证入口、元信息、文件引用及清单；不等于发布入库 |
| `publishTechnique` | 技法身份、sealed 引用、预期发布头、`operationId` | 新的可用库版本；无自动授权或绑定 |
| `readTechniqueFile` | 本轮已准入的技法引用、`path` | 受宿主绑定、权限代次、版本和预算控制的内容及证据凭据；模型不能传任意本机路径 |
| `saveTechniqueFromAnalysis` | 分析产物引用、生成快照引用、`operationId` | 同一来源结果对应的库草稿；重复保存返回同一候选，不附带方案 |

所有修改请求的同一 `operationId` 必须具有同一内容摘要。相同 ID/相同请求返回已保存结果；相同 ID/不同请求返回 `operation_conflict`。先查已有回执，再检查当前草稿版本，避免响应丢失后的正确重试被误判为版本冲突。模型工具不负责发明幂等键，宿主把工具调用身份映射为稳定操作键。

常用错误语义：`draft_conflict`、`operation_conflict`、`invalid_entry`、`invalid_reference`、`version_missing`、`authorization_revoked`、`file_exceeds_budget`、`draft_cancelled`。错误关联具体可修复对象，不把不可恢复契约错误无限重试。

### 5.2 落盘、提交与恢复

文件变更先写同目录的暂存代次，校验并刷盘；以原子替换切换草稿头，头中包含本次操作键、请求摘要和结果引用。提交完整版本同样先形成不可变目录与清单，再更新可用引用。SQLite 索引在正式文件提交后更新，失败可以重建，不要求两套正文双向同步。

生成完成的快照先落盘，再通过现有 Artifact/任务生命周期提交引用。若文件已落盘而数据库或响应失败，重试利用同一草稿及操作回执找回快照；不得重复生成内容。没有数据库引用的暂存产物不对库和自动读取暴露，恢复时按归属操作处理。

同一草稿的取消和 seal 通过锁及预期版本串行判定：取消先提交则 seal 被拒绝；seal 先提交则完整快照保留，但是否交付仍由 Run 的取消结果决定，不复活已取消任务。已生成文件不等于已经发布可用版本。

恢复必须从持久的 `draftId + draftRevision/treeDigest` 和操作结果取得当前状态，不能重新创建空草稿覆盖已完成文件。复用共享 Run/Task/Artifact 记录；草稿文件操作回执只负责保存一致性，不新建另一套 Agent 执行或进度账本。

## 6. 分析与技法生成结果

一次来源分析首版最多交付一个写作技法，可含任意符合限额的作者文件；不同机制可在这个技法内部有条件组织。材料不足时交付零个。一次生成多个独立技法不进入首版，不能将多文件支持误实现为自动生成一个方案。

来源分析产物与技法生成结果分开：

```json
{
  "analysisSchemaVersion": 3,
  "sourceRevisionId": "source-revision-id",
  "techniqueResult": {
    "status": "generated",
    "candidate": {
      "draftId": "draft-id",
      "techniqueId": "host-generated-id",
      "versionId": "content-tree-digest"
    },
    "evidenceRefs": ["validated-observation-id"],
    "scopeNotes": [],
    "reason": ""
  }
}
```

当前分析结构已升级为 `analysisSchemaVersion: 3`，历史版本只读；旧结果不可恢复执行或经旧候选接口发布。来源事实、故事概览及证据继续使用各自适当的分析字段；文案来源不因生成技法而被要求编造小说人物或剧情。

| 情况 | 技法结果 | Run 与页面行为 |
| --- | --- | --- |
| 部分或全部观察支持一个可用技法 | `generated`，candidate 必有完整 sealed 引用 | 分析可完成；展示入口和文件；允许保存为库草稿，未自动发布 |
| 没有观察能支持可用机制 | `insufficient_material`，candidate 为 null，保存 `reason` 与证据范围说明 | 正常完成并保存分析；展示“未提炼出可用技法”；没有技法保存按钮，不重试来硬凑结果 |
| 文件写入、模型调用、输入证据校验或提交失败 | 运行错误，保留可恢复草稿及已完成的上游产物 | 沿现有失败/恢复机制；不得假装为材料不足，也不把半成品标 generated |
| 用户取消 | Run cancelled，保留已有记录但不继续发布 | 明确取消状态，不靠最终回复反转任务状态 |

`scopeNotes`、`reason` 及证据关联属于分析结果，不能自动追加到 `SKILL.md`。仅正文中影响创作选择的使用条件需要保留。查看历史分析不以存在技法为前提；对来源分析的追问必须识别 generated/insufficient 两种结果。

结构检查由宿主负责，内容生成规范由内置提示词指导。没有“模型复核通过才允许用户看到草稿”的新门槛；结构未完成的内容不能宣称可用。真实证据错误和材料不足必须区分，不能为了得到成功状态吞掉故障。

## 7. 来源输入与内置提示词装配

共同内容提示以 [总计划第 5.5 节](2026-09-07-writing-techniques-1.0.0-plan.md#55-核心生成提示词草案复核修订版) 为当前草案。实现时在 `backend/domains/writing_technique_prompts.py` 集中维护并导出装配函数，文件名中的 technique 与产品术语一致；不要求模型编写应用内置生成提示词文件。

生成调用的输入分别包含：来源类别和冻结范围、用户关注点、已校验观察及证据引用、现有草稿状态、真实文件工具契约。小说与文案共享生成规范与产物格式，来源分析适配保持各自语义。生成模型可以通过授权范围的只读来源访问补读原文，不默认每次拼入全部来源。

移除上下游“固定六条观察”的语义丢弃规则。提取与归并按非重复机制、来源支持和上下文预算保留观察；容量不足采用分批、持久化和继续读取，不无限放大单次输出，也不将被预算省略的材料标为已经充分覆盖。具体每调用预算沿现有运行限制，并记录尚未处理的来源范围。

生成模型读取观察目录时可按关注点深入相关观察与来源证据，不把省略观察等同不存在。模型自选文件组织不改变源范围权限，不以检索工具恢复已被上游永久丢弃的观察。

质量示例仅装配与任务相关的少量指引，开发验证原文不默认注入生产提示词。提示词内容摘要、模型配置、来源版本与最终产物引用进入现有 Run 证据或诊断元数据，具体原始 Provider 内容沿当前私有诊断边界处理。

## 8. 导入导出、归档与备份

独立技法导出支持作者文件目录和 ZIP；单文件可以导出 Markdown。方案导出 ZIP 内含方案及所有冻结成员版本，并带宿主生成的交换清单；不只导出不可解析的本机引用。

导入的同 ID 同版本同摘要可以去重；同 ID 不同内容不覆盖已有对象。用户预览选择“作为新技法/方案”或“更新现有草稿”，默认作为新对象。导入方案如果缺少依赖只能作为待修复草稿，不能发布或选择使用；导入不携带原机器授权和本轮模式。

新结构日常“从库中删除”采用归档语义：从新选择及自动候选中隐藏，保留被方案、小说和历史 Run 引用的版本；引用显示不可用并引导调整，不自动替换或静默改写方案。归档触发对应执行授权失效。重新启用只恢复库可见性，不恢复旧授权代次。

首版不自动回收历史版本。真正物理删除只处理被明确删除且没有任何现存草稿、方案、小说、Run 或待提交操作引用的内容。暂存垃圾回收不能删除仍被恢复任务引用的目录。

完整备份覆盖库元数据、作者文件、完整版本、尚可恢复的草稿、Run 输入快照和 SQLite 正式业务状态。备份在统一保存屏障下取得一致数据库与文件头集合，按摘要校验依赖；恢复到暂存目录验证后切换，失败保留原环境。缓存索引可重建。

本次旧格式一次性退役遵循 [清理清单](2026-09-07-writing-techniques-legacy-retirement.md)，与新结构日常归档不同：旧技法/方案数据不转换，历史来源和 Run 保留只读。旧备份导入需在服务恢复可用前完成相同退役，不暂时开启旧执行入口。

## 9. P0 验收与实现入口

| 契约场景 | 必须观察到的结果 |
| --- | --- |
| 手动模式、小说有长期绑定、本轮未选择 | 无自动搜索、无隐式主方法或历史选择注入 |
| 本轮上传但不入库，准入后重启 | 同一 Run 从原快照恢复；新轮次不自动使用；库中不出现新技法 |
| 手动选方案但缺一个成员 | 明确失败且不开始部分使用；自动候选则跳过该方案 |
| 已读入口后撤销授权 | 下一次受影响的调用停止；恢复不借旧快照绕过撤销 |
| 两文件已写完，进程中断 | 草稿头与完整文件代次一致，继续修改而非重新创建 |
| seal 已落盘但响应丢失 | 相同操作重试返回同一快照，没有第二份候选或额外版本 |
| 取消与提交并发 | 按先完成的持久操作一致处理，取消任务不会被后续成功回复复活 |
| 分析有事实但无可提炼机制 | 分析正常保存，insufficient_material 可查看，无占位技法或故障重试 |
| 索引删除后重建 | 作者内容、授权、小说绑定及历史版本均不改变 |
| 旧备份恢复 | 无关数据可用，旧技法不可执行，不删除历史 Run，不重新种入旧默认方法 |

生成内容与独立使用样本见 [评估清单](2026-09-07-writing-techniques-evaluation.md)。P0 完成意味着这些契约、清理范围和验证输入已明确；不表示以上行为已经实现或真实 Provider 已通过。

后续工程实现可调整具体模块拆分、SQL 表名、缓存策略和跨平台文件锁实现，但不能改变本文定义的作用域、授权、结果状态和数据保留行为而不更新文档与验收。P1–P5 按总计划推进。
