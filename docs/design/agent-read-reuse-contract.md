# PurrTypos Agent 读取结果与上下文复用规范

状态：剧本、Writing、小说分析均已接入公共材料准备器，并有模拟模型回归测试。
使用现有 PurrA 接口，实施范围为 PurrTypos 宿主代码；真实 Provider 验证另行记录。

## 1. 目标与适用范围

在保证材料权限、版本、完整性和模型输入可用性的前提下，复用成功的只读结果，
减少重复底层读取、重复模型工具请求和同一模型输入中的重复正文。

PurrTypos 各 Agent 使用同一宿主复用约定。业务工具显式声明是否允许复用、数据身份、
授权范围和有效性验证方式；未声明的工具不自动缓存。写入、审批、发布及其他
副作用工具继续使用各自的执行和幂等契约，不能用读取缓存代替执行。

复用不保证模型永不请求重读，也不保证跨模型请求的输入 token 免费。无状态
模型请求仍需携带本次需要的上下文；Provider 的输入缓存计费是独立能力。

## 2. 所有权

| 层 | 责任 |
| --- | --- |
| PurrTypos 公共 Application / Composition | 统一材料复用流程、输入材料去重、按任务补入缓存内容、注册适配器、关联实际输入回执 |
| 业务工具 / Domain | 只读与可复用声明、参数规范化、资源身份、当前权限、版本有效性、输出所需证据及业务显示名 |
| Infrastructure | 缓存存储、并发读取合并、源数据变更失效、容量控制及持久化 |
| 前端 | 展示已持久化的执行与复用事实，不推断命中，不隐藏真实工具请求 |
| 现有 PurrA 接口 | 接收宿主上下文及证据元数据，继续执行既有预算、工具协议、压缩、检查点和 Run 生命周期 |

各业务 Agent 共用 PurrTypos 的材料准备逻辑，依赖注入由 Composition 负责。
材料身份、有效性和覆盖范围均由宿主管理，不在 PurrA 增加业务判断或复用策略。
宿主通过既有扩展接口参与上下文装配，不复制模型轮次或恢复状态机。

## 3. 三种状态必须独立判断

1. 缓存可用：存储中存在成功结果，且对当前调用者与请求仍有效。
2. 输入已装配：所需内容通过预算与信任边界处理，实际进入某次模型输入。
3. 当前仍可用：后续请求、压缩或恢复后，所需内容仍存在于当前模型输入中。

历史读取回执只证明过去的提供事实，不能证明后续请求仍带有正文；缓存存在
也不能证明模型已拿到材料。回执证明输入已提供，不声称模型一定理解或采用。

## 4. 统一执行流程

1. 宿主声明当前任务所需的材料及完整性要求，只预装相关材料，不倾倒整个缓存。
2. 按当前工具权限与数据授权验证需求，再解析实际资源、参数默认值和版本。
3. 所需的同一材料已经完整存在于本次输入时，保留已有内容，不追加重复正文。
4. 本次输入缺少材料且缓存有效时，由上下文阶段补入；缓存未命中、无效或需要
   不同范围时，保留原有业务读取工具供模型按需取得材料。
   上下文准备不伪装成模型工具调用，也不建立独立的模型执行链路。
5. 预算装配完成后记录真实输入证据，保留工具名、参数和完整结果。完整结果
   指该参数范围内的工具响应，不代表整部书或整个交付物。目录、摘要不能满足
   要求正文的业务准入；预算不足时整份跳过，仍可按需调用工具。
6. 业务准入接受满足其资源、版本和覆盖范围要求的实际输入证据，不再强制要求
   同一 Run 中必须先发生指定名称的工具调用。预装不能伪造工具调用或成功事件。
7. 模型仍主动请求读取时，保留真实调用及参数；命中有效缓存就返回缓存结果，
   跳过底层查询，并记录命中事实。其他授权工具和请求范围仍可由模型选择。

已经发出的模型工具调用必须获得协议要求的响应。去重不能留下孤立调用、
伪造 tool call ID，或用模型无法解析的引用代替它当前缺失的正文。

## 5. 身份、有效性与恢复

- 复用身份包括工具及输出契约版本、规范化后的有效参数、资源身份、授权范围
  和真实数据版本或可验证指纹。相同文案或相同文本哈希不能替代权限与来源验证。
- 参数省略和显式默认值只有经业务解析为同一请求后才可复用；影响结果的范围、
  分页或过滤条件必须保留。调用 ID 和 Run ID 不应无条件阻断跨单元复用；
  依赖当前任务身份的结果仍须隔离任务范围。
- 权限每次使用时重验。明确请求不可变旧版本可以复用该版本；请求“当前版本”
  时必须重新确认它的指向。不能证明新鲜度的动态数据不自动复用。
- 同一有效身份的并发读取应合并；源数据修改与缓存失效应保持一致，不能让
  变更后的读取继续获得旧结果。失败或不完整结果不能充当成功材料。
- 压缩、裁剪、续跑和新执行单元建立输入时，重新核对内容与证据的对应关系。
  正文被移除后，历史回执保留为审计事实；材料需要时重新补入或读取。
- 缓存可以跨授权的执行单元共享，输入证据必须归属实际接收它的 Run 和模型
  调用。不能直接把另一 Run 的“已经提供”事实复制为本 Run 的事实。
- 预装继承原有不可信资料标记，不把缓存内容提升为 system 指令；容量不足时
  按材料需求与预算处理，不静默丢失必需正文后继续声称证据完整。

## 6. 事件与验收

分别记录模型请求工具的次数、底层实际读取次数、缓存命中、上下文预装及最终
输入大小。工具命中缓存仍是一次真实模型工具请求；没有工具请求的预装不得
增加工具调用数。公开展示使用持久化事实，诊断与正文不自动进入公开执行面板。

确定性验收至少覆盖：

| 场景 | 必须证明的结果 |
| --- | --- |
| 同一输入再次需要相同材料 | 正文只装配一次，来源与覆盖范围可核对 |
| 新执行单元需要有效缓存材料 | 模型首次输入已有所需正文，无需强制读取往返；业务证据校验通过 |
| 材料仅有目录、摘要或被压缩移除 | 不满足完整正文要求；按需补齐后才允许继续 |
| 版本、权限、参数范围变化 | 旧结果不会冒充新请求所需材料，越权需求被拒绝 |
| 并发、源数据变更与进程恢复 | 无重复有效读取、无过期提供，恢复后的输入证据仍准确 |
| 模型主动再次调用 | 正常返回缓存或新读取结果，真实调用事件完整保留 |
| 副作用工具 | 不因缓存而跳过执行或改变审批、幂等约束 |
| 至少两个不同业务 Agent | 使用相同 PurrTypos 公共编排实现和现有 PurrA 接口 |

验收覆盖 PurrTypos 公共编排、业务准入、缓存适配和持久化回放。真实 Provider
验证比较调用次数、输入大小和产出完整性，不能仅凭缓存命中率宣称收益。

## 7. 接入落点与交付边界

沿用现有 `ContextProvider` / `StagedContextProvider`、`ContextBlock`、
`ContextEvidenceReceipt` 和 Core 的证据检查点机制。有效性、覆盖范围与业务
资源映射由宿主定义，通过既有上下文及证据元数据传递；是否满足产出条件由
业务校验器判断，不用自由文本 Prompt 充当控制逻辑。

公共材料准备器为 `backend/application/prepared_read_context.py`，三个业务
Profile 均通过该入口提供材料。材料保持不可信正文属性，按身份与内容摘要去重，
完整装入后才附加输入证据；准入查询最新实际模型输入中的证据。

| Agent | 材料来源 | 已覆盖的执行场景 |
| --- | --- | --- |
| 剧本 | `screenplay_tool_cache`；沿用工具、项目、集数、版本和来源授权范围 | 同一集下一场直接使用已有分集材料，产出准入通过，无新增读取调用 |
| Writing | `writing_tool_cache`；书籍、当前章节和目录范围隔离，源表变更触发失效 | 已读章节进入下一次模型首轮输入；正文更新后失效并重新读取；跨书隔离 |
| 小说分析 | 宿主已绑定的不可变单元输入 | 完整分析材料直接进入首轮输入，允许直接提交结果；主动重读仍正常执行 |

Writing 当前声明复用的工具包括章节、章节目录、人物、设定、背景和大纲读取。
动态检索、Memory、写作方法检索及副作用工具不纳入此缓存；未声明有效性契约
的工具保持原有行为。源数据变更失效在数据库事务中完成，缓存容量有界。

此项不包含修改 PurrA 源码、公开契约、包版本或宿主框架依赖。测试模拟模型
选择直接使用材料和主动读取两条路径，不保证真实模型永远不会主动重读。
