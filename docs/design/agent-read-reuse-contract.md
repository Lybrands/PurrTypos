# PurrTypos Agent 按需读取与透明缓存规范

状态：剧本、Writing、小说分析均采用显式工具读取。本文是当前合同；任何把历史读取正文或缓存正文自动装入 Provider 输入的实现都不兼容。

## 1. 目标与适用范围

模型初始输入保持任务相关且可解释：自动上下文只承载执行规则、紧凑事实、稳定标识、授权范围和必要的有界检索结果。原作正文、剧本交付物正文、候选产物正文和完整分析单元输入只能在模型显式调用读取工具后进入该 Run 的消息历史。

读取缓存仍可跨轮次或授权范围内的 Run 复用，但它只优化工具 handler 的底层查询。缓存存在、缓存命中和模型已经收到内容是三件不同的事。

本规范覆盖 PurrTypos 的只读工具、工具缓存、模型输入和候选准入；写入、审批、发布及其他副作用工具继续遵守各自的执行与幂等合同。

## 2. 所有权

| 层 | 责任 |
| --- | --- |
| PurrA Core | 执行 ContextProvider、模型轮次、工具轮次、事件和 Run 生命周期；不解释产品材料或缓存 |
| PurrTypos Profile / Application | 提供紧凑任务上下文、决定可用工具、建立业务证据门槛 |
| Domain tools | 定义参数、授权范围、返回结构和业务显示名 |
| Infrastructure | 在真实工具调用内查询或命中缓存，处理隔离、失效、并发和容量 |
| 候选 Projector / validator | 只依据当前 Run 的成功工具事件、工具结果和来源收据准入 |
| 前端 | 展示持久化工具事实；不把缓存命中伪装成未执行工具 |

Core 的上下文窗口和 token budget 只是容量上限，不授予宿主把可用材料全部注入 Prompt 的权限。产品缓存策略不得进入 PurrA 通用代码。

## 3. 必须独立判断的状态

1. 缓存可用：指定工具、规范化参数、资源版本和授权范围存在有效成功结果。
2. 工具已执行：当前 Run 产生了匹配的工具调用、成功结果和完整 Operation 事件。
3. 内容仍在模型历史：本轮消息保留对应工具结果，尚未被压缩或裁剪移除。

只有第 2 项能满足“本 Run 已读取”的业务门槛。历史 Provider 输入收据、其他 Run 的调用、缓存行或内容哈希都不能替代它。

## 4. 统一执行流程

1. Profile 为当前阶段提供规则、清单、ID、版本绑定和授权边界，不加载工具等价正文。
2. 模型根据任务显式调用可用读取工具，并传入所需范围。
3. 工具重新校验项目、资源、版本、权限和参数；校验在查缓存之前完成或进入缓存身份。
4. 有效缓存命中时，handler 返回缓存结果；未命中时读取权威数据并在事务内写入缓存。
5. 无论命中与否，Core 都记录本次真实工具调用、结果和 Operation 终态；来源工具同时记录当前 Run 的来源收据。
6. 模型只从本次工具结果获得正文。需要不同范围、不同表示或被压缩移除的内容时，再次调用工具。
7. 候选写入和完成投影只接受当前 Run 的成功工具事件及具体结果；缺少依赖时返回可纠正错误，不从缓存或旧输入补证据。

已经发出的工具调用必须获得协议要求的响应。缓存不能消除模型已发出的 tool call、伪造 call ID、跳过公开 Operation，或把正文改成模型无法解析的内部引用。

## 5. 上下文与返回体边界

允许自动进入 Provider 输入的内容：

- system/developer 执行规则和工具 schema；
- 项目、阶段、任务、版本和授权范围的紧凑清单；
- 用户明确选择且由对应 ContextProvider 合同声明的有界检索结果；
- 当前 Run 已发生的 assistant/tool 消息历史。

禁止自动进入 Provider 输入的内容：

- `screenplay_tool_cache` 或 `writing_tool_cache` 中扫描出的正文；
- 其他 Run 的工具结果或 Provider 输入证据；
- 完整原作章节、完整交付物、完整候选产物或完整小说分析单元输入；
- 同一交付物的结构化内容与渲染文本双份复制。

`readScreenplayDeliverable` 每次只返回一个 `content` 字段，并用 `representation=structured|text` 标明表示；省略参数时优先选择非空结构化内容，否则选择文本。需要另一表示时显式再次读取。

目录、摘要、片段和完整正文具有不同覆盖语义。业务需要完整正文时，目录或搜索摘要不能满足准入。

## 6. 缓存身份、失效与恢复

剧本场景显式调用 `getScreenplaySceneContext` 后，可在同一工具结果中取得锁定版本的本集分集结构。原作分析目录及无效小节键的错误响应提供合法 `readRequests`；这些请求只涉及当前已授权文档，不能扩大版本或来源范围。具体边界见[剧本执行耗时优化](2026-09-06-screenplay-execution-efficiency.md)。

- 身份至少包括工具合同版本、规范化参数、项目/书籍范围、授权范围和影响结果的版本绑定。
- 权限和资源归属每次调用都要验证；相同文本或哈希不能替代来源与授权。
- 源表变更在数据库事务边界使相关缓存失效；失败、越权和不完整结果不得缓存为成功材料。
- 缓存容量有界；旧合同的缓存 key 版本升级后不得命中新合同。
- 并发相同读取可合并或串行复用，但每个模型发起的调用仍获得自己的工具响应与事件。
- 恢复只重放当前 Run 的持久消息和事件，不扫描缓存来重建 Prompt。若所需工具结果已不在可用历史中，模型重新读取。

## 7. 业务落点

| Agent | 正文入口 | 缓存与证据合同 |
| --- | --- | --- |
| 剧本 | `readSource*`、`readScreenplayDeliverable`、`getScreenplayEpisodeContext`、`readScreenplayTaskDependencies` | `screenplay_tool_cache` 仅在 handler 内命中；候选只认当前 Run 的成功读取和具体 dependency 结果 |
| Writing | 章节、人物、设定、背景和大纲读取工具 | `writing_tool_cache` 仅在 handler 内命中；首轮 Provider 输入不扫描同书缓存 |
| 小说分析 | `readNovelAnalysisInput` | 单元输入保留在宿主 ExecutionState，首次 Provider 输入不含正文；提交前必须真实读取 |

动态 Memory/写作方法检索继续遵循各自 ContextProvider 或 Retriever 合同，不因为存在通用工具缓存而自动提升为正文预载。

## 8. 确定性验收

| 场景 | 必须证明的结果 |
| --- | --- |
| 缓存已预热，新 Run 首轮调用模型 | 输入不含缓存正文；模型仍可看到读取工具 |
| 模型显式读取且缓存命中 | 返回完整工具结果，`fromCache=true`，工具 Operation 和来源收据仍完整 |
| 写候选前未读取 | 准入失败；旧 `purrtypos.prepared_read` 收据也不能放行 |
| 依赖 Part 未读取或读取了错误 Part | 候选写入和完成投影失败 |
| 版本、权限或参数范围变化 | 旧缓存不命中，越权请求被拒绝 |
| 源数据变化 | 旧缓存失效，下一次真实工具调用返回新内容 |
| 交付物读取 | 单次结果不同时包含结构化正文和渲染正文 |
| 压缩、恢复或新执行单元 | 不从缓存隐式恢复正文；需要时重新调用工具 |

测试必须分别报告：确定性源码回归、缓存命中行为、Provider 输入捕获、真实 Provider E2E。没有凭据或余额时，真实 Provider E2E 是未验证面，不能用模拟模型测试冒充通过。
