# Agent 架构改造阶段总览

| 阶段 | 主题 | 核心学习点 |
|---|---|---|
| 1 | 工具契约 | 模型说明书与后端能力必须一致 |
| 2 | 人工审批 | 高风险动作由宿主控制，不由模型自我批准 |
| 3 | Planner / Executor | 计划、待办、执行和步骤工具范围是不同概念 |
| 4 | 上下文与记忆 | 动态预算优于固定比例，完整轮次优于逐消息裁剪 |
| 5 | 可观察性 | `run_id` 把一次执行的因果链连接起来 |
| 6 | Planner 评测 | 用稳定案例验证结构化计划，不依赖印象 |
| 7 | 人工质量评审 | 运行正确不等于回答有用 |
| 8 | 真实 Pilot | 真实模型能暴露适配器和流程组合问题 |
| 9 | Runtime Regression | 将真实事故永久转化为回归契约 |
| 10 | 可靠性恢复 | `blocked/canceled/failed` 与幂等重试必须分离 |
| 11 | 性能成本 | 先定位浪费，再优化上下文 |
| 12 | 发布门禁 | 测试、灰度、回滚需要不同证据和决策 |
| 13 | 安全红队 | 模型和检索内容都不可信，宿主必须守住不变量 |
| 14 | 架构收口 | 模块边界、运行手册和发布清单使知识可持续 |
