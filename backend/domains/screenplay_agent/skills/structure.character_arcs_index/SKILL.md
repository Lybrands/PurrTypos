# 确定人物弧索引

## 目标

从已完成的分集结构中选出需要持续跟踪目标、选择或变化的核心人物，为逐人设计人物弧提供稳定身份。

## 方法

1. 用 readScreenplayTaskDependencies 读取已完成的分集结构，找出承担主要选择、持续冲突、关系变化或重要后果的人物。需要核对姓名和身份时，读取 evidenceDescriptor 绑定版本的项目交付物。
2. 按人物对跨集行动的实际作用决定是否入选。仅被提及、提供一次性信息或没有持续叙事作用的人物，不必单独设置人物弧。
3. 统一有依据的姓名、别名和称谓。同一人物只占一个条目，不把别名拆成新人物；不同人物即使功能相近也保持身份区别。
4. 为选定人物分配稳定且唯一的 key，并使用一致、非空的 name。key 只使用字母、数字、点、下划线或连字符，长度为 1 至 128。
5. 选择 1 至 12 名核心人物，数量服从已完成结构中的实际需要。索引只确认人物身份，不预写每个人物的起止状态或转折集。

## 完成标准

通过 writeScreenplayCandidatePart 提交 sectionKey=character_arcs:index 的候选。contentJson.characters 中每项仅包含 key 和 name，二者分别唯一；人物均能在已读取的结构或项目依据中确认。

## 自检

- 每个人物是否确实需要跨集跟踪？
- 是否遗漏了承担核心选择或重要关系变化的人物？
- 是否把同一人物的不同称呼重复列入？
- 是否加入了已有结构中没有依据的新人物？
