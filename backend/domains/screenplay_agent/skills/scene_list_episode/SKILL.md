# 当前集场景规划

## 目标

把当前集已采纳的结构展开为有因果承接的场景序列，使每场承担明确的行动与变化。

## 方法

1. 用 readScreenplayDeliverable 读取绑定的 structure 版本和当前 episodeNumber，确认本集目标、冲突、关键转折、集末钩子及叙事边界。其他集或项目材料只用于必要的衔接核对。
2. 以人物需要采取的行动安排场景，明确人物想争取什么，以及谁或什么形成实际阻力。场景数量由完整行动链和项目形式决定，不把每条信息单独分成一场。
3. 为每场确定 objective、conflict、turn 和 synopsis。turn 应说明本场之后局面、信息、关系或选择条件发生了什么变化，并影响下一场的起点。
4. 按出场顺序检查场景之间的时空、人物状态和因果连接。heading 写明内外景、地点与时间；必须跨越过程时，保留足以理解状态变化的衔接。
5. 保留当前集和既有场景的身份。修订沿用原 scene id，新增场景使用全剧唯一 id；只规划本集，不提前完成其他集的主要事件。

## 完成标准

通过 writeScreenplayCandidatePart 提交 sectionKey 为当前集的候选。contentJson.scenes 非空、顺序清楚，只含当前集；各场具备 id、episodeNumber、heading、objective、conflict、turn、synopsis。场景梗概足以指导逐场写作，不展开完整对白或剧本正文。

## 自检

- 本集结构要求的关键变化是否都有场景承载？
- 是否存在没有作用的重复场，或只有解释而没有实际推进的场景？
- 场景的转折是否改变后续行动条件？
- 新增内容与绑定结构、人物知情范围和世界规则是否一致？
