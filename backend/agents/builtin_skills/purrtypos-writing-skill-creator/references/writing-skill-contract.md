# 写作 Skill 组织原则

- 一份分析生成一份完整 Skill；多个写法在同一目录树中协同组织。
- `SKILL.md` 是唯一入口，应当足以让创作 Agent 判断是否使用以及下一步读取哪个文件。
- YAML 头部使用以下可检索结构；字段按实际内容填写，不为凑数量制造同义项：

  ```yaml
  ---
  name: 技法名称
  description: 一句话说明它解决的写作问题
  metadata:
    retrieval:
      intents: [读者或创作者可能提出的目标]
      contexts: [适用的场景或文本状态]
      objectives: [希望改善的叙事效果]
      keywords: [可用于召回的技法术语与近义表达]
      exclusions: [容易误用但不适用的情况]
  ---
  ```

- `intents`、`contexts`、`objectives`、`keywords` 至少有一类非空；`exclusions` 只在确有边界时填写。
- 检索元数据必须脱离原作成立，不写来源作品的专有名词、剧情事实、原句或证据编号。
- 一个文件能够清楚表达时不拆分；只有辅助内容具有独立、按需读取价值时才建立子目录。
- 目录按创作需要组织，不按来源章节、观察数量或生成批次组织。
- 正文提供可执行但可调整的写作方法；不虚构必然效果，不生成强制模板。
- 示例仅在有助于理解操作时使用，并采用与来源无关的原创情境。
